# Проверка условий до calibration и holdout inference

26.09.2026, runtime `0.9.0`. [План v2](./frozen-profile.md) проверял соответствие готового отчёта. CLI теперь проверяет условия до первого обращения к модели: неподходящий запуск не должен расходовать закрытые данные даже тогда, когда его отчёт впоследствии был бы отвергнут.

Для `evaluate --split calibration` нужен `--plan` v2. Для `evaluate --split holdout` дополнительно обязательны `--frozen-calibration` и `--reverse-options`. Fit проверяется по seal, dataset/plan SHA, полному model identity, набору calibration case/group IDs, схемам вопросов и порядку timestamps. Пропущенные условия и неподходящие артефакты отвергаются до загрузки весов. После загрузки полный raw profile сравнивается с закреплённым; при расхождении backend не получает ни одного входа.

`--frozen-calibration` служит свидетельством завершённого fit. Температура не применяется: отчёты calibration/holdout сохраняют raw logits с `calibration.status: uncalibrated`, а `qualify` пересчитывает baseline и fitted варианты из одного набора измерений. Применяющий температуру флаг `--calibration` запрещён для этих splits. Development-оценка может работать без квалификационного плана; квалификационные аргументы с development отвергаются, чтобы не создавать ложную связь экспериментов.

Команды актуализированы в [протоколе](./README.md#план-fit-и-holdout). Это намеренное изменение CLI: старые команды calibration/holdout без плана теперь завершаются с кодом 1. Низкоуровневый Python `evaluate` остаётся механизмом исполнения и используется unit fixtures; CLI является точкой preflight. Последующая проверка evidence при `calibrate`/`qualify` сохранена.

Локальные артефакты не являются авторизацией или одноразовым пропуском: preflight не препятствует доверенному оператору повторно запустить опыт, прочитать dataset вручную или использовать Python напрямую. Он предотвращает случайное использование несогласованных настроек; организационная независимость holdout остаётся обязательной.

Основа — разделение выбора модели и итоговой оценки, описанное в [практиках scikit-learn по предотвращению утечки данных](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage). Конкретные preflight-проверки и аргументы CLI определены контрактом Агат.

## Проверки

Unit-тесты подтверждают отсутствие загрузки backend при пропущенном плане и отсутствие вызова `score`/выходного файла при изменённом runtime profile. Проверяются старый формат, будущие даты, чужой plan SHA, потерянные case/group IDs, другой deadline/profile, отсутствие fit, отсутствие перестановки и случайное применение температуры. Сквозной CPU-тест использует реальный дочерний процесс, проходит оба splits и проверяет raw calibration status в holdout-ответах.

[Реальный прогон](./evidence/2026-09-26-preflight/verification.json) на Apple M1 Max / 32 ГиБ прошёл 12 calibration-вызовов, fit, затем 12 прежних синтетических holdout fixtures в двух порядках. Все 36 результатов совпали с [профилем](./evidence/2026-09-26-preflight/runtime-profile.json): 2048 токенов, cache 128 МиБ, deadline 2000 мс. Температура совпала с прежним опытом; [qualification](./evidence/2026-09-26-preflight/qualification.json) осталась `not_qualified`, routing выключен. Это инженерный повтор, реальный source-review holdout не использовался.

Отдельный реальный запуск с deadline 1000 вместо 2000 мс завершился кодом 1 и сообщением о несовпадении профиля до `evaluate`; выходной файл не появился. Отсутствие вызова `score` на этой ветке проверено CLI-тестом со spy. Runtime suite: 91 тест, 3 необязательных MLX skip. Временные процессы CLI закрыты, постоянный сервис не запускался.

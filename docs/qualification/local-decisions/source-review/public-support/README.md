# Публичные вопросы для независимой разметки

Подготовка: 08.10.2026 MSK. Это отдельный корпус наблюдавшихся публичных
вопросов о программном обеспечении и инфраструктуре. Он расширяет материал
для **классификации**, но не заменяет разрешённый поток заказчика Agat,
владельцев пилота, человеческую разметку или предметную qualification.
Публикация вопроса установлена по официальному API; истинность описанной
автором неисправности и правильность ответов сообщества не установлены.

## Выбор источника и границы достоверности

Изучен [BANKING77 авторов PolyAI](https://github.com/PolyAI-LDN/task-specific-datasets/tree/57ec275d8078af65b7731c2a98be812d844a6d6b).
[Исходная статья](https://aclanthology.org/2020.nlp4convai-1.5/) описывает
13 083 клиентских вопроса и 77 намерений. Проверены опубликованные train/test,
категории и лицензия CC BY 4.0, включая соответствие Git blob SHA и SHA-256.
В снимке обнаружены семь групп одинаковых нормализованных текстов между
train/test. [Исследование ошибок меток](https://aclanthology.org/2022.insights-1.19/)
дополнительно показывает, почему опубликованная метка не равна проверенному
эталону; его автоматические кандидаты нельзя объявлять подтверждёнными ошибками.
Текущая [карточка decider](https://huggingface.co/Mapika/decider-2b) называет
Banking77 среди обучающих источников. Полная независимость от конкретного
старого checkpoint по его карточке не доказана. Поэтому BANKING77 не выбран
для независимой квалификации decider. Контракт runtime также допускает
не более десяти вариантов; превращать 77 намерений в иную задачу без оценки
такого преобразования было бы некорректно.

Выбраны ru.stackoverflow, Ask Ubuntu и Server Fault через официальный
[метод questions](https://api.stackexchange.com/docs/questions).
Весь доступный поток в заранее выбранном UTC-окне запрашивается по времени
создания, без отбора по тегам, голосам, ответам или ожидаемым меткам. Сбор
закрепляет метаданные [revision decider b37f7e1](https://huggingface.co/api/models/Mapika/decider-2b/revision/b37f7e1ba3fbc9238004cf531fabbee2619973fd):
окно должно начинаться позже сообщённого API `lastModified` этого checkpoint.
Это временная проверка для данного checkpoint, а не доказательство независимости
от будущих моделей или отсутствия всех смысловых пересечений с обучением.

Первое выбранное окно: `[2026-09-29T00:00:00.000Z, 2026-10-07T00:00:00.000Z)`.
Оно полностью завершено на момент сбора. Даты здесь в UTC; дата подготовки
выше — московская. Ограничения: до 31 дня, до пяти страниц на сайт в этом
запуске, по 100 вопросов на страницу. Неполная пагинация, API error или backoff
дают `failed`; такой снимок не импортируется. При backoff сбор прекращается,
следующий запуск допускается после указанной задержки. Это следует
[правилам API](https://api.stackexchange.com/docs/throttle); одинаковые запросы
не следует повторять чаще раза в минуту. API не обещает атомарный снимок между
страницами: удаление или редактирование записей во время сбора остаётся ограничением.

## Лицензия и подготовка заданий

Принимаются только записи с явным `content_license = CC BY-SA 4.0`, именем
и прямой ссылкой на профиль автора на исходном сайте. Отсутствующая лицензия
не подставляется по дате, хотя [официальная политика](https://stackoverflow.com/help/licensing)
указывает CC BY-SA 4.0 для вкладов после 02.05.2018. В каждый review-пакет
включены источник Stack Exchange, ссылка на вопрос, имя/профиль автора,
лицензия и указание преобразования HTML в текст, согласно
[требованиям атрибуции](https://stackoverflow.blog/2009/06/25/attribution-required/).
Исходные тексты сохраняют CC BY-SA 4.0 и не перелицензируются под Apache-2.0
проекта. Сырые снимки и пакеты остаются в игнорируемом `docs/private/`.

В запрос входят только заголовок и тело вопроса. Ответы, теги, score,
принятый ответ и признаки репутации не используются как признаки или gold.
Текст не переводится и не исправляется. Задание предлагает пять вариантов:
incident, enhancement, access, other, insufficient; последний допускает
воздержание. Это наша рубрика основной запрошенной помощи, а не исходные
метки Stack Exchange и не вывод о произошедшем инциденте.

Записи одного известного автора на одном сайте и дубли нормализованного
тела объединяются транзитивно в группы. Исходный текст запросов при этом
сохраняется. Прежний seed `agat-source-review-2026-09-26-v1` используется
без поиска лучшего распределения. Личность между сайтами, общая первопричина
разных вопросов и остальные зависимости не установлены. Размеры групп и
split — описательные counts, не число доказанно независимых наблюдений.

## Воспроизведение

[Сборщик](../../../../../scripts/acquire-public-support-sources.py) требует
committed sources до сетевых запросов. Он сохраняет точные байты ответов,
URL/параметры, SHA-256, размеры, source commit и seal журнала. Seal проверяет
целостность локального артефакта, а не является подписью Stack Exchange.
[Импортер](../../../../../scripts/import-public-support-pool.py) требует
отдельный SHA файла acquisition и сверяет каждый снимок, полную пагинацию,
границы времени, модель, атрибуцию и контракт запроса до создания output.
Каталог должен быть новым и находиться в `docs/private`; файлы создаются
с режимом 0600, каталог — 0700, перезапись запрещена.

```bash
python3 scripts/acquire-public-support-sources.py \
  --start-at 2026-09-29T00:00:00.000Z \
  --end-at 2026-10-07T00:00:00.000Z \
  --sites ru.stackoverflow askubuntu serverfault \
  --max-pages-per-site 5 \
  --output-dir docs/private/public-support-acquisition-20261008
shasum -a 256 docs/private/public-support-acquisition-20261008/acquisition.json
python3 scripts/import-public-support-pool.py \
  --acquisition docs/private/public-support-acquisition-20261008/acquisition.json \
  --acquisition-file-sha256 REPLACE_WITH_ACTUAL_64_HEX_SHA \
  --output-dir docs/private/public-support-review-20261008
python3 -m unittest scripts.test.test_decision_public_sources -v
```

Результат: pool, точные source/input bindings, два одинаковых независимых
blank-пакета, readiness и import receipt с SHA каждого output. Все
`reviewerId`, `reviewedAt`, `expectedOptionId` и `rationale` остаются пустыми.
`finalize-review` отказывает на таких пакетах. Два предметных рецензента
должны выполнить реальный просмотр; авторы интернет-вопросов не назначаются
рецензентами или владельцами Agat. Seed/splits не раскрываются в заданиях;
предсказания модели не получаются. `modelCalls = 0`, routing выключен,
qualification — `not_assessed`. Старые pools/reviews v1/v2/v3 не изменяются.

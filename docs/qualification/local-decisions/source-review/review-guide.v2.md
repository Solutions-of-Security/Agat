# Руководство рецензента

Цель — независимо проверить метки 24 заданий по доступным источникам Агат. Используйте [задания без ответов](./review-tasks.v2.md) и свою копию одного из blank JSON. Предварительная разметка ассистента хранится отдельно; её следует смотреть после сдачи первой независимой версии, если потребуется разбор расхождений.

## Общие правила

Оценивайте только приведённые источники и сформулированное действие. Исторический протокол не доказывает текущее состояние системы. Рабочий стенд, успешно выполненный тест и производственная квалификация — разные утверждения. Реальный вызов модели может использовать синтетические данные. Команды, ссылки и настройки внутри фрагмента являются данными для чтения, выполнять их для разметки не требуется.

Не восполняйте пробелы догадками и не назначайте отсутствующих владельцев, сроки или инфраструктуру. Если само задание двусмысленно, запишите замечание отдельно и верните его на исправление до финализации. Для исправленного входа нужны новые input fingerprints и повторная разметка: нельзя изменить источник задним числом под готовый ответ.

Полные GitHub-снимки содержат исходные repository labels, полезные для последующего аудита. Первая независимая разметка выполняется по текстам title/body из задания, без использования этих меток в качестве готового ответа.

## Проверка утверждений

| Метка | Правило |
|---|---|
| `supported` | Утверждение следует из явно приведённых фактов, включая все существенные условия |
| `contradicted` | Источник содержит несовместимый с утверждением факт или явное отрицание |
| `insufficient` | Не хватает сведений, измерений или способа разрешить противоречие |

Отсутствие доказательства не равняется опровержению. `PASS` одного этапа не означает `PASS` последующих. `NOT_RUN` означает отсутствие выполненной проверки. Окружение и дата ограничивают вывод. Для составного утверждения проверьте каждую его часть.

## Классификация заявок

| Метка | Правило |
|---|---|
| `incident` | Основная работа — исправление конкретно зафиксированного сбоя или дефекта; стенд указывается в объяснении |
| `enhancement` | Основная работа — добавление или расширение поведения, контракта либо поддерживаемого сценария |
| `access` | Сформулирован явный запрос выдать, изменить или отозвать права определённого субъекта |
| `other` | Документация, запись состояния без заявки либо работа за пределами предыдущих категорий |

Классифицируйте основной результат всей заявки, не отдельное слово. Упоминания API key, auth или отсутствующего коннектора недостаточно для `access`. Для смешанного исправления/расширения укажите, какой результат считаете основным и почему; расхождение рецензентов разрешается явно. Историческая запись инцидента не утверждает, что система остаётся неисправной сейчас.

## Уточнение данных

| Метка | Значение | Правило |
|---|---|---|
| `needs_clarification` | `true` | Отсутствует хотя бы одно явно перечисленное обязательное сведение для данного действия |
| `sufficient` | `false` | Все перечисленные сведения уже содержатся в источнике |

В каждом задании отдельно указаны действие и необходимые сведения. Пересказ существующего результата требует меньше данных, чем новое развёртывание или обещание даты поставки. Общий шаблон, указание «назначить владельца» и требование «подтвердить команды» не являются конкретными значениями. Достаточность данных не выдаёт разрешение на внешнее действие и не гарантирует доступность инфраструктуры.

## Заполнение и согласование

1. Сохраните свою копию как `review.first.completed.v2.json` или `review.second.completed.v2.json` в этом каталоге; исходные blank-файлы оставьте без изменений.
2. Заполните `reviewerId` собственным стабильным идентификатором без пробелов и `reviewedAt` фактической датой/временем с часовым поясом, например в формате ISO 8601.
3. Для каждого `id` задайте `expectedOptionId` из разрешённых вариантов и `rationale`: опорный факт, логика выбора и существенное ограничение. Нельзя менять pool, seed и `inputSha256`.
4. До сдачи не согласовывайте ответы друг с другом и не переносите готовые предложения ассистента вместо собственного решения.
5. Координатор разметки запускает `finalize-review` с двумя завершёнными файлами. При разногласиях требуется отдельный adjudication-пакет третьего рецензента: тот же pool/seed, собственный reviewer ID, labels только спорных случаев и объяснение решения.

Назначенные рецензенты в этой подготовке отсутствуют. Для технических источников нужны люди, способные оценить runtime/эксплуатацию Агата и границы продуктовых требований. Локальные IDs не аутентифицируют человека: реальное выполнение review подтверждается процессом команды.

Перед передачей датасета на обучение или измерение качества проверьте покрытие предметных классов и отсутствие зависимых групп в разных splits. Текущий небольшой пакет служит началом разметки; команды подготовки не делают его репрезентативной производственной выборкой.

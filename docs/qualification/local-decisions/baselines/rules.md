# Предметные правила: ограниченный baseline по заголовку заявки

26.09.2026. Эвристика `ticket-title-rules v1` проверена на тех же **15 development-примерах из двух групп**, что decider, Qwen Base и генеративный Qwen3. Она верно выбрала две метки и приняла только один ответ. Для этого корпуса покрытие слишком мало; правило не включено в runtime или маршрутизацию. Девять holdout-примеров не запускались.

## Область применения и исходы

[Реализация](../../../../scripts/lib/decision_rules.py) получает только публичный `Request`. Она поддерживает один вопрос классификации и точную семантику четырёх вариантов `incident / enhancement / access / other`; порядок вариантов и request ID на выбор не влияют. Другие вопросы, Boolean/Score и изменённые описания получают отказ без выбранной метки.

Первый источник должен начинаться с явного заголовка `KEY-123: действие` или строки roadmap `| KEY-123 | P1 | действие | ...`. Категория определяется первым глаголом из небольшого зафиксированного списка: исправление ошибки/сбоя, новое поведение, выдача/изменение/отзыв доступа либо подготовка документа/протокола. Одинокое слово «доступ» не превращает разработку механизма доступа в запрос прав. Отрицание, условие, несколько действий, конфликтующие явные заголовки и неизвестная форма дают `selectedOptionId: null`.

Текст ниже заголовка не интерпретируется. Поэтому противоречие между заголовком и телом, ложный заголовок или скрытое отрицание могут сделать выбранную метку неверной. Это эвристика извлечения одного признака, а не доказательство смысла документа или защита от всех prompt injections. Источник остаётся недоверенными данными. Выбор `access` никогда не выдаёт права.

Совпадение правила не является вероятностью. В результате нет logits, confidence и распределения; принятие означает единственный поддерживаемый шаблон заголовка. `other` сохраняет собственную метку, но имеет `abstain`, как в исходном контракте. Полный отказ с `null` не засчитывается как правильная метка `other` или `insufficient`.

## План и результаты

[План](./evidence/2026-09-26/rules-plan.json) с SHA исходников зафиксирован перед вычислением ответов. При проектировании правил уже были просмотрены development-входы и прежние development-выводы; результат **не является слепой независимой проверкой**. Классификатор не получает expected labels, rationale или family. Инструмент отвергает calibration/holdout до вызова правила. Пороги моделей, разметка и splits не менялись.

| Кандидат | Правильных меток, исходный / обратный порядок | Принято, исходный / обратный | Ошибок среди принятых, исходный / обратный |
|---|---:|---:|---:|
| Правила по заголовку | 2/15 / 2/15 | 1 / 1 | 0 / 0 |
| decider-2b | 14/15 / 14/15 | 8 / 10 | 0 / 1 |
| Qwen3.5 Base | 7/15 / 7/15 | 2 / 3 | 1 / 2 |
| Qwen3 8B, генеративный JSON | 9/15 / 8/15 | 12 / 12 | 4 / 5 |

Модельные результаты повторно валидированы из прежних файлов; новый model inference не выполнялся. Правила принятия различаются: вероятностный порог модели, валидная генеративная метка и совпадение эвристики не задают одинаковый допустимый риск. Одна принятая метка без ошибки не подтверждает надёжность автоматизации.

В [результате правил](./evidence/2026-09-26/rules-result.json) оба правильных выбора относятся к classification: `agat-source-009 → enhancement` и `agat-source-010 → other`. Из шести классификационных случаев две длинные строки roadmap отклонены из-за отрицаний в описании; два сообщения о сбое не имеют явного заголовка заявки. Все четыре evidence- и пять clarification-задач вне области правила. Итого 13 отказов без выбора и один выбор abstain-категории; автоматическое покрытие — **1/15 = 6.7%**, в classification — 1/6. Порядок вариантов не изменил ни одного ответа.

CPU-время правила имело p95 0.074 мс в исходном порядке, но 13 быстрых отказов входят в этот показатель. Его нельзя сравнивать с задержкой полноценного модельного решения как равнозначное ускорение. Модельные timings относятся к другим прогонам и средам.

[Сравнение](./evidence/2026-09-26/rules-comparison.json) сохраняет все метки, confusion matrices, показатели по семействам и ограничения. Результат правил признан недостаточным для широких семантических задач. Список выражений после просмотра результата не расширялся: это стало бы дальнейшей подгонкой к малому development-набору.

## Проверки и воспроизведение

[12 тестов](../../../../scripts/test/test_decision_rules.py) проверяют четыре типа действий, отрицания и составные запросы, отличие упоминания доступа от его выдачи, конфликт заголовков, изменённый контракт, все 24 перестановки вариантов, недопуск holdout, отсутствие gold в predictor и отбрасывание подменённых результатов. [Verifier сравнения](../../../../scripts/compare-decision-rules.py) воспроизводит правила, проверяет seals, input/order bindings, frozen code и пересчитывает summary. Дополнительная арифметическая сверка независимо посчитала correct/accepted/errors по каждой строке. [Протокол](./evidence/2026-09-26/rules-verification.json) — `verified`; это проверка воспроизводимости, не независимая экспертная оценка меток.

```bash
python3 scripts/evaluate-decision-rules.py \
  --dataset docs/qualification/local-decisions/development/evidence/2026-09-26/dataset.json \
  --plan-output docs/qualification/local-decisions/baselines/evidence/new-run/rules-plan.json \
  --output docs/qualification/local-decisions/baselines/evidence/new-run/rules-result.json

python3 scripts/compare-decision-rules.py \
  --dataset docs/qualification/local-decisions/development/evidence/2026-09-26/dataset.json \
  --plan docs/qualification/local-decisions/baselines/evidence/new-run/rules-plan.json \
  --rules docs/qualification/local-decisions/baselines/evidence/new-run/rules-result.json \
  --generative docs/qualification/local-decisions/baselines/evidence/2026-09-26/qwen3-generative.json \
  --logits docs/qualification/local-decisions/development/evidence/2026-09-26/decider-scores.json \
           docs/qualification/local-decisions/development/evidence/2026-09-26/qwen-base-scores.json \
  --output docs/qualification/local-decisions/baselines/evidence/new-run/rules-comparison.json
```

Все output создаются эксклюзивно. Исторические исходники, данные и результаты не перезаписываются. Runtime остаётся `0.12.0`: правила — отдельный offline baseline и не меняют модельный профиль.

Основание выбора: [Google Rules of ML](https://developers.google.com/machine-learning/guides/rules-of-ml) рекомендует начинать с простой эвристики и избегать разрастания сложных правил; [scikit-learn о data leakage](https://scikit-learn.org/stable/common_pitfalls.html) требует отделять данные разработки от проверки. Здесь принят проектный вывод: оставить узкий baseline для сравнения, а проверяемую арифметику отчёта выполнять из явных числовых записей. Утверждать понимание свободного текста по совпадению слов нельзя.

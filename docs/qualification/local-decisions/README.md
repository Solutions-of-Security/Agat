# Первый эксперимент с локальными решениями

Дата: 21.09.2026. Реализованный компонент и команды запуска: [локальный runtime](../../local-decision-runtime.md). Эксперимент проверяет прямое получение типизированных решений из открытых весов на Mac. Он не подтверждает равенство Jev и не допускает автоматическую маршрутизацию в Агат.

Продолжение от 26.09.2026: [разметка, калибровка и проверка отдельной выборки](./calibration/README.md). Ниже сохранены результаты первого эксперимента с runtime 0.1.0.

## Методика

[development.v1.json](./development.v1.json) содержит 36 синтетических, явно размеченных примеров на русском:

- 12 проверок утверждений по источнику: поддержано / опровергнуто / недостаточно данных;
- 12 классификаций заявок: сбой / развитие / доступ / другое;
- 12 проверок необходимости уточнения обязательных данных: Boolean.

Разметка `synthetic-authored`: составлена при разработке, без независимого предметного рецензирования. Три общих шаблона образуют три группы. Разные строки и перестановки не являются независимым human-reviewed holdout; доверительные границы продуктового качества по этому набору не заявляются.

Кейсы включают отрицания, отсутствующие сведения, противоречивые источники и команды, внедрённые в исходный текст. Порядок правильной метки меняется между примерами. Для каждого запроса дополнительно проверяется обратный порядок вариантов. Оригинальные 36 примеров и 36 перестановок учитываются раздельно.

Одинаковы prompt `agat.state-first.letters.v1`, температура `1.0`, лимит 2 048 токенов, BF16 без квантования и policy `agat.shadow.v1`: вероятность ≥ 0.8, отрыв ≥ 0.1. Порог зафиксирован до прогона и не подбирался по этим ответам. Явные варианты `insufficient` и `other` дают abstain. Принятое решение здесь означает только прохождение экспериментального порога.

Среда: Apple M1 Max, 32 ГБ unified memory, macOS 26.6.2, Python 3.13.12, MLX 0.32.2, mlx-lm 0.31.3. Два checkpoint последовательно исполняются одним адаптером на одном устройстве; загрузка файлов может происходить в фоне. Это рабочий ноутбук без изоляции фоновой нагрузки. Ревизии и контрольные суммы файлов присутствуют в каждом JSON-отчёте.

Все входы decider в этом наборе имеют 104–155 токенов. Измеряется время `DecisionEngine.decide`: валидация, токенизация, forward, расчёт распределения и policy. Загрузка/проверка весов, HTTP, очередь coordinator, retrieval, approvals и внешние действия в это число не входят. Metal/файловые кеши могли быть прогреты предыдущими проверками; `firstRequestMs` означает первый запрос процесса, а не гарантированный cold start машины. Память — peak аллокаций MLX, не полный RSS системы.

Квантили latency вычисляются методом nearest rank. NLL ограничивает вероятность истинной метки снизу значением `1e-15` для конечного численного результата. ECE считается по десяти равным интервалам вероятности выбранного варианта; это описательная метрика маленького development-набора, не гарантия калибровки.

У базовой модели исходная разбивка: evidence — 7/12, classification — 5/12, clarification — 6/12. Сильное изменение качества при перестановке вариантов — существенное ограничение готовой языковой основы для этого способа чтения logits. Повышение точности на обратном порядке не использовалось для выбора удобного порядка или изменения policy.

В этом эксперименте decider устойчивее и точнее исходной основы, но разница зависит от порядка. Маленький синтетический набор не позволяет переносить эти проценты на реальные процессы. Скорость двух вариантов сопоставима; отдельные стартовые выбросы не доказывают преимущество одной модели. Проверяется эффект двух checkpoints при одинаковом текстовом scorer, а не универсальное лидерство в классе локальных моделей.

## Как повторить

Установите окружение и скачайте pinned models по [инструкции runtime](../../local-decision-runtime.md). Затем из корня репозитория:

```bash
npm run test:decision
AGAT_DECISION_TEST_MANIFEST=.local-models/decisions/decider-2b.json \
  .venv/decision/bin/python -m unittest decision_runtime.tests.test_mlx_integration -v
.venv/decision/bin/python -m decision_runtime evaluate \
  --manifest .local-models/decisions/decider-2b.json \
  --dataset docs/qualification/local-decisions/development.v1.json \
  --split development --reverse-options \
  --output docs/qualification/local-decisions/evidence/new-decider-run.json
```

Для базовой модели замените manifest на `qwen3.5-2b-base.json` и имя нового отчёта. Перезапись существующего evidence запрещена. Опциональная переменная `AGAT_DECISION_TEST_EVIDENCE` сохраняет сверку logits и соседний `*-http.json` файл. В обычном CI два GPU-теста пропускаются, 24 теста контракта/eval/HTTP выполняются без MLX. Для loopback-тестов необходим доступ к локальным сокетам.

Отчёты содержат SHA dataset, implementation SHA исходников runtime, полную identity модели, политику и все решения. `qualityGate: not_configured` обозначает отсутствие утверждённых критериев продукта; exit code 0 означает отсутствие ошибок исполнения, а не достижение требуемой точности. Измерения вариантов порядка не удваивают знаменатель coverage или число групп.

Закреплённый SHA dataset: `7a9ca3bc9552080bdc003fc1dd5e72db13453e06b7cdca5cfcc082388d6d51fa`. SHA реализации: `cfaf951bb8addcf5ff32d4f5c4ef48e6e05db54cca432e4442c784da4951b8bf`. Изменение любого исходного `.py` файла runtime меняет implementation SHA; для новой версии нужны новые evidence-файлы.

## Решение по результатам первого этапа

Техническая возможность локального быстрого scorer подтверждена. Готовность decider к автоматическим действиям по выбранному порогу не подтверждена: 12% ошибок среди принятых ответов на простом development-наборе требуют дальнейшей работы.

До подключения к маршрутам нужны разрешённые реальные примеры, независимые экспертные метки, критерии допустимого риска и покрытия, отдельный calibration split и закрытый holdout. Отсутствие обязательного поля в уже структурированной форме следует проверять кодом. Модель полезно оценивать там, где нужна интерпретация свободного текста; threshold tuning на этих 36 примерах не заменит такой проверки.

После выбора пригодной модели последует worker capability/profile, проверка ответа coordinator, bounded retries/cancellation и project-scoped хранение решений. Ни состояние текущих процессов, ни права, ни обязательные согласования этим экспериментом не менялись. Fine-tuning, RL и публикация внешнего сервиса не выполнялись.

## Проверка поставки

- `npm run test:decision`: 24 теста прошли, два opt-in GPU-теста пропущены в стандартном прогоне.
- Оба GPU-теста отдельно выполнены на каждом checkpoint: реальные HTTP-вызовы, сверка с полным выходом и повтор после других вопросов — PASS. На шести проверенных примерах расхождение logits равно 0.0.
- Два eval-прогона: 144 вычисления, включая перестановки; ни одной ошибки backend. Метрики, соответствие input/model/source fingerprints и все распределения повторно проверены по сохранённым JSON.
- `npm run docs:check`: 12 Node-тестов и два Python-теста прошли, каталог процессов актуален. После добавления последнего evidence проверены 644 локальные ссылки в 103 Markdown-файлах; внешние URL и anchors не входят в эту проверку.
- `architecture_audit.py --profile generic` для руководства и паспорта эксперимента: 0 ошибок/предупреждений. `uv pip check`: совместимы все 34 пакета MLX-окружения. `git diff --check`: PASS.

Полный `npm test` и повторная квалификация существующих процессов не выполнялись: код coordinator, web, Temporal и текущего worker этим этапом не изменён. В корневой `npm test` добавлен новый `test:decision`, поэтому общий CI будет выполнять эти проверки вместе с существующими suites.

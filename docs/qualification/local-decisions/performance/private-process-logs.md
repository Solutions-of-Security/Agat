# Приватные process logs без позднего копирования

28.09.2026. Полный повтор после [исправления временного storage](./temporary-postgres-volumes.md)
запущен на `fc805ee19fbaf7fc123702d116180fd96919ba62` с неизменным
профилем runtime 0.12.1. После warmup моделей и начала integration build
файловая система сообщила ENOSPC. Успешные phase reports и итоговый `launcher.json`
не получены; этот запуск не является пройденным Temporal/RAG gate.

## Воспроизведённая потеря диагностики

Cleanup выполнялся до архивирования process logs, но сами журналы находились
в `TemporaryDirectory`. Создание постоянного приватного каталога после cleanup
завершилось ENOSPC; исключение не позволило записать итоговый report. Выход из
контекста удалил временные журналы. Сохранены исходный plan, build log и CLI
traceback; исходную причину остановки workload по утраченным журналам восстановить
нельзя. Ошибка выделения места для архива подтверждена непосредственно traceback.

Три fixture-сценария воспроизвели дефект без заполнения настоящего диска:
недоступное создание каталога после запуска, недоступное создание файла журнала
после запуска и невозможность создать приватный каталог до запуска.
Первые два теряли итоговый report, третий успевал запустить процессы.

## Исправление и проверки

[Launcher](../../../../scripts/run-temporal-real-rag.py) создаёт приватный каталог
и открывает оба process log непосредственно в нём до первого owned subprocess.
`O_CREAT | O_EXCL` и режим `0600` сохраняют запрет перезаписи и доступ только
владельцу. Ошибка открытия второго журнала закрывает первый handle; модели
не запускаются. После workload/cleanup считаются SHA уже сохранённых файлов,
дополнительного копирования из временного каталога нет.

Это согласуется с документированным жизненным циклом
[TemporaryDirectory](https://docs.python.org/3/library/tempfile.html#tempfile.TemporaryDirectory),
который удаляет содержимое при выходе из контекста, и семантикой
[эксклюзивного открытия файла](https://docs.python.org/3/library/os.html#os.open).
Временный каталог по-прежнему используется для shim и control files.

[Шесть tests](../../../../scripts/test/test_temporal_log_retention.py) исполняют
launcher с явно синтетическими process/API fixtures. Проверены поздние ENOSPC,
исходный failure в отчёте, SHA и `0600`, запрет перезаписи, отсутствие process
admission без журналов и закрытие частично открытых handles. Если уже итоговый
report невозможно записать, запуск остаётся ошибкой, но существующие process
logs сохраняются. Это не обещает запись новых bytes при полностью заполненном
диске или сохранение данных после аппаратного отказа.

В первом полном targeted запуске 76 проверок прошли. Четыре live Docker tests
остановились до создания fixtures: `docker image inspect` не ответил за прежние
10 секунд. Docker daemon не перезапускался, чужие ресурсы не удалялись.
Повтор полного real-model gate требует снова доступного Docker и достаточного
дискового пространства. Профиль, inference deadline и Workflow-код не менялись;
qualification и SLO остаются открытыми.

Полный offline docs check: 12 Node и 436 Python tests — pass; четыре Docker
tests пропущены по opt-in. Process catalog и 2128 локальных ссылок в 232 Markdown
файлах проверены. [Checks и SHA исходников/журналов](./evidence/2026-09-28/private-process-logs/checks.json)
явно отделяют offline pass от недоступных live tests.
[Сводка неудачного реального запуска](./evidence/2026-09-28/private-process-logs/failed-attempt.json)
не содержит данных о ресурсах компьютера; исходные артефакты сохранены в `docs/private`.

# Точный CSV-отчёт в процессе с согласованием

26.09.2026. [Расчёт по закреплённым CSV-записям](./source-records.md) подключён к существующим шагам процесса Агата. Подготовленный граф показывает отчёт владельцу и **после подтверждения сохраняет Markdown, исходный CSV и расчётный JSON**. Отклонение не создаёт этих артефактов. Модель не вызывается и не переписывает числа.

Это процесс для одного заранее подготовленного снимка. Арифметика вычисляется при подготовке; изменение входа запуска не подменяет источник. Для новых данных требуется новая подготовка и публикация соответствующего графа. Автоматического чтения обновившегося файла или подключения к бизнес-системе здесь нет.

## Подготовка и выполнение

```bash
python3 scripts/prepare-source-report-process.py \
  --source docs/qualification/local-decisions/performance/evidence/2026-09-26/source-records-source.csv \
  --mapping docs/qualification/local-decisions/performance/evidence/2026-09-26/source-records-mapping.json \
  --name 'Отчёт SUPPORT-DEMO: июль и август 2026' \
  --output docs/qualification/local-decisions/performance/evidence/new-source-process/bundle.json \
  --process-json docs/qualification/local-decisions/performance/evidence/new-source-process/process.json
```

CLI создаёт новые файлы только под `docs`. [Актуальный bundle примера](./evidence/2026-09-26/source-process/bundle-with-request-support.json) содержит исходный текст и SHA его байтов, mapping, полный точный расчёт, graph и ожидаемые SHA/размеры трёх файлов. [Process JSON](./evidence/2026-09-26/source-process/process-with-request-support.json) — готовое тело обычного API создания процесса. CLI не обращается к работающему приложению и не устанавливает процесс автоматически.

Генератор также принимает [mapping отдельных заявок](./request-records.md). Адаптер выбирается по `schemaVersion`; одинаковые дубли исключаются из сумм, конфликтующие значения останавливают подготовку. Согласование и набор файлов одинаковы для обоих форматов.

| Шаг API | Действие |
|---|---|
| `POST /api/v1/processes` | Передать содержимое `process.json` в выбранном проекте; получить ID |
| `POST /api/v1/processes/:id/publish` | Опубликовать граф и получить номер версии |
| `POST /api/v1/processes/:id/start` | Указать полученную `version`, `startMode: "now"`, `resultDestination: "history"` и описание запуска в `input` |
| **Согласования → выбранный запуск** | Открыть данные предыдущего шага, проверить отчёт и исходные условия, разрешить продолжение либо отклонить |
| **Запуск → Технические детали → Артефакты** | Скачать `source-report.md`, `source.csv`, `calculation.json` после подтверждения |

Используются обычные авторизация и project scope приложения. Установка пакета `internal-report` v1 не меняется; это отдельный подготовленный процесс. Частичный запуск запрещён через `allowPartialStart: false`, внешние MCP-инструменты не разрешены.

## Что связывает результат с источником

[Библиотека подготовки](../../../../scripts/lib/report_process.py) повторно вычисляет source binding и арифметику, строит Markdown и включает их в опубликованный graph. Источник сохраняется с исходными UTF-8 байтами, включая BOM и CRLF. Числа и source SHA отображаются в отчёте; подробные ячейки, позиции, формулы и точные дроби остаются в JSON.

Значения передаются через literal JSON и однопроходные `json.*` templates. Последовательности вроде `{{ input }}` в исходном CSV экранируются в literal JSON, декодируются обратно при сохранении и не исполняются как выражения процесса. Ввод запуска не участвует в вычислении или замене закреплённых данных.

`verify_process` пересобирает весь bundle по источнику и mapping: подмена graph, снятие согласования, изменение ожидаемого файла или расчёта отклоняются даже после пересчёта внешнего seal. Проверку применяет CLI перед выдачей process JSON. Обычный редактор процессов остаётся доступен дизайнеру; вручную изменённый graph уже не соответствует этому bundle и требует отдельной проверки.

Существующий лимит template — 100 000 символов после JSON-экранирования. Слишком большой источник отклоняется без усечения; этот путь рассчитан на небольшие таблицы. Проверка SHA и чисел не удостоверяет автора, полноту или соответствие объявленной совокупности реальному источнику. Дедупликация выполняется только в формате отдельных заявок и только по объявленному ключу. Flags достоверности и qualification остаются `false`; решение человека хранится отдельно в обычном audit согласования.

## Проверки

Первый агрегатный вариант: четыре новые Python-проверки вместе с арифметикой и CSV binding — **26/26 pass**. Проверены побайтовое сохранение BOM/CRLF, template-подобный текст, подмена повторно запечатанного bundle, лимит размера, CLI и запрет перезаписи файлов. После добавления формата отдельных заявок — **38/38 pass**, HTTP-сценарий прошёл для обоих форматов.

[HTTP-проверка](../../../../apps/coordinator/test/source-report-process.test.ts) создаёт и публикует graph через настоящий coordinator с временной SQLite. Проверены остановка на согласовании без артефактов, отказ старта с каждого шага сохранения, устойчивость к подменённому input, подтверждение и отклонение. После подтверждения все три скачанных файла совпадают с ожидаемыми SHA/размерами, а CSV — с исходными байтами. Первая версия теста ошибочно ожидала HTTP 200 на согласовании; после сверки с существующим API ожидание исправлено на 204 и весь тест прошёл.

Согласования в тестах выполняет тестовый клиент на синтетических данных. Это проверка механизма и неизменности файлов, не человеческая предметная приёмка. Новый Temporal/PostgreSQL deployment и реальные бизнес-данные этим сценарием не проверялись.

[Итоговая перепроверка](./evidence/2026-09-26/source-process/verification.json) связывает bundle, код, логи и шесть скриншотов. [Отчёт для просмотра](./evidence/2026-09-26/source-process/report.md) совпадает с ожидаемым Markdown-артефактом. Проверка документации после добавления генератора: 12 Node- и 114 Python-тестов — pass; coordinator typecheck/build и web build — pass.

Браузерный путь прошёл на desktop 1440×1000 и Pixel 7 412×839: запуск → раскрыть данные в согласовании → разрешить продолжение → технические детали → артефакты → скачать CSV с проверкой SHA. Использован установленный Chrome через Playwright, поскольку Browser plugin отсутствует. Проверены URL/заголовок, непустая страница, отсутствие overlay и ошибок console/pageerror, границы текста, кнопки и скачивание; скриншоты просмотрены.

Пояснение к согласию сокращено до видимой в карточке длины.

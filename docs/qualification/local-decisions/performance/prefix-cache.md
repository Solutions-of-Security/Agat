# Общий префикс state: ускорение и изменение распределений

26.09.2026. Offline-прототип повторного использования state выполнил 180 ответов по 36 синтетическим вопросам. Копии cache совпали со свежим раздельным вычислением и выдержали 72 проверки неизменности исходного состояния. Однако разделение state/question изменило вероятности относительно полного forward до 0.034753, около 3.48 процентного пункта. **Численная эквивалентность не принята; cache не включён в serving.**

## Основание и протокол

После [проверки обычного батча](./batching.md) изучены закреплённые исходники mlx-lm 0.31.3. [Qwen3.5](https://github.com/ml-explore/mlx-lm/blob/v0.31.3/mlx_lm/models/qwen3_5.py) использует одновременно `KVCache` для full attention и `ArraysCache` для свёртки/рекуррентного состояния. Копировать только KV недостаточно. Официальный [evaluation-код](https://github.com/ml-explore/mlx-lm/blob/v0.31.3/mlx_lm/evaluate.py) вычисляет независимые продолжения общего контекста через `copy.deepcopy(cache)`. Эта стратегия применена в [прототипе](../../../../scripts/lib/decision_prefix.py); совместимость не предполагается заранее, а проверяется на реальных вычислениях.

Исходный [synthetic robustness plan](./evidence/2026-09-26/robustness-plan.json) остаётся неизменным. Выбраны первые четыре случая каждой длины: single/conflict/missing/injection с фактом в начале. Получены 12 state. Для каждого — исходный вопрос и два новых вопроса о коде отдельно в записи А и записи Б. Варианты не меняются; gold labels не используются. 36 вопросов — зависимые синтетические варианты, а не новые размеченные production-примеры.

Префикс в точности равен токенизации `Context:\n{state}`, суффикс — прежней отдельной токенизации вопроса/вариантов/`Answer: (`. Их конкатенация проверяется против неизменённого `encode_request`; нет усечения или иной границы BPE. Длины префиксов — 402/914/1938 токенов; суффиксов — 110/96/97. Поэтому полные длины групп — 512/498/499, 1024/1010/1011 и 2048/2034/2035 токенов.

Модель и профиль: `Mapika/decider-2b`, runtime 0.10.0, MLX 0.32.2, mlx-lm 0.31.3, cache allocator 128 МиБ, предел 2048, Apple M1 Max 32 ГиБ. [План](./evidence/2026-09-26/prefix-plan.json) сохранён до inference и содержит все входы, hashes токенов, SHA инструментов и полный исходный профиль. Критерий прежний: абсолютные Δ logits и вероятностей ≤0.0001, точное совпадение метки, статуса и причины abstain; температура 1, policy 0.8/0.1.

Сравниваются четыре пути:

1. `serial`: исходный полный forward без cache, 36 ответов.
2. `full_cache`: тот же полный вход со свежим нативным cache, 36 ответов.
3. `split_fresh`: новый prefix prefill и отдельный suffix для каждого вопроса, 36 ответов.
4. `shared_prefix`: один prefill на state, независимая глубокая копия всех слоёв cache на вопрос; 36 ответов в прямом порядке и 36 в обратном.

Всего 180 измеряемых ответов, 12 общих prefill и 228 backbone-вызовов с учётом внутренних prefill в `split_fresh`. Отдельно три прогрева на первом коротком вопросе: четыре backbone-вызова. Длительность опыта — 72.663 секунды. Внутренний бюджет 300 секунд проверяется между вызовами, внешний watchdog ограничивал процесс 360 секундами. Exit 2 обозначает непройденный численный критерий, а не незавершённый прогон.

## Распределения и изоляция

| Сравнение | Проверок | Нарушений критерия | Максимальная Δ logit | Максимальная Δ вероятности |
|---|---:|---:|---:|---:|
| Полный fresh cache против serial | 36 | 0 | 0 | 0 |
| Раздельное свежее вычисление против serial | 36 | 33 | 0.1875 | 0.034753 |
| Общий prefix против serial, оба порядка | 72 | 66 | 0.1875 | 0.034753 |
| Общий prefix против раздельного свежего | 72 | 0 | 0 | 0 |
| Обратный порядок вопросов против прямого | 36 | 0 | 0 | 0 |

Во всех сравнениях метка, статус и причина abstain совпали. Все 72 проверки исходного prefix cache после каждого продолжения подтвердили неизменность. Снимки включают обе разновидности состояния, shape/dtype, размеры и SHA конечных значений после точного преобразования BF16 в float32. Кэш привязан к точным prefix tokens и identity backend; другой state или профиль отвергается до продолжения.

Разница связана с раздельным вычислением prefix/suffix: создание свежего cache при полном forward ничего не изменило, а раздельный путь уже отличается. Повторное использование копий дополнительной разницы на проверенных входах не добавило. Это не доказательство эквивалентности для других вопросов, более длинных текстов или иной архитектуры. Конкретный численный kernel здесь не установлен.

## Время с учётом подготовки префикса

| Группа исходной длины | Полный serial, мс/вопрос | Полный fresh cache | Раздельный fresh | Общий prefix на три вопроса |
|---:|---:|---:|---:|---:|
| 512 | 231.092 | 233.548 | 269.886 | 134.867 |
| 1024 | 443.020 | 450.651 | 474.786 | 204.826 |
| 2048 | 878.161 | 884.391 | 901.793 | 347.738 |

Таблица использует только прямой порядок. В каждой группе — четыре state × три вопроса. Для общего prefix суммируется **один измеренный prefill на каждые три вопроса** плюс все suffix-вызовы, затем сумма делится на 12. Копирование cache входит во время suffix-вызова. Обратный порядок служит отдельной проверкой изоляции и не используется для искусственного снижения амортизированной стоимости.

В измерение вызовов не входят пересчёт контрольных сумм cache, проверки результата, HTTP и очередь. Фазы не чередовались, прогрев охватывал только первый короткий вопрос. Это наблюдаемое снижение вычислительной стоимости в повторяющемся synthetic state, без причинной оценки production-speedup или p95. Обновление calibration/eval потребуется даже при сохранении меток, потому что распределения изменились.

Сумма `nbytes` объектов общего cache после prefill — 25 829 376 / 32 120 832 / 44 703 744 байт для трёх групп. Она включает внутренние выделенные буферы объектов и не равна отдельному пику RAM. Cumulative peak active MLX за весь опыт — 4 980 244 190 байт. Нет постоянного словаря cache, межпроектного обмена или записи тензоров на диск: в offline-процессе живёт только один общий state и текущая копия.

## Проверка и решение

[Результат](./evidence/2026-09-26/prefix-result.json) содержит все logits, вероятности, времена и проверки. [Независимый verifier](../../../../scripts/verify-decision-prefix.py) пересчитал seals, input bindings, порядок/полноту, softmax, policy, 252 сравнения и таблицу времени. [Свидетельство](./evidence/2026-09-26/prefix-verification.json) также подтверждает точное совпадение 12 исходных serial-ответов с отдельным предыдущим процессом batching-диагностики. Полные cache tensors и token arrays не сохранялись; их внутренние проверки verifier повторно не выполняет.

Шесть CPU-тестов проверяют точную границу токенов, запрет чужого state/profile и oversize до forward, фиксацию плана, полноту опыта, различение численного дрейфа и загрязнения cache, остановку при мутации исходного cache. Это дополняет реальные вычисления, но не заменяет их.

Оптимизация оставлена отдельным offline-инструментом. Нужны собственный execution profile и применимые независимые calibration/eval перед использованием в runtime. Текущие данные не позволяют принять новое распределение или смягчить пороги; исходный runtime остаётся без межзапросного cache.

```bash
.venv/decision/bin/python scripts/diagnose-decision-prefix.py \
  --source-plan docs/qualification/local-decisions/performance/evidence/2026-09-26/robustness-plan.json \
  --manifest .local-models/decisions/decider-2b.json \
  --policy docs/qualification/local-decisions/policy.shadow.v1.json \
  --plan-output docs/qualification/local-decisions/performance/evidence/new-run/prefix-plan.json \
  --output docs/qualification/local-decisions/performance/evidence/new-run/prefix-result.json

python3 scripts/verify-decision-prefix.py \
  --evidence-dir docs/qualification/local-decisions/performance/evidence/2026-09-26 \
  --output docs/qualification/local-decisions/performance/evidence/new-run/prefix-verification.json

python3 -m unittest scripts.test.test_decision_prefix -v
```

Все output создаются эксклюзивно. Verifier связывает версию кода с планом; изменение инструментов требует сохранённой версии для проверки старого опыта.

# Прекращение устаревших embedding-ответов после отказа renewal

Дата: **27.09.2026**. Продолжение [проверки настоящего worker после потерянного COMMIT](./embedding-worker-recovery.md).

## Воспроизведённое поведение

Обычный Python worker получил embedding lease и начал настоящий HTTP-вызов локального OpenAI-compatible test endpoint. Endpoint удерживал ответ. Аренда была принудительно просрочена в одноразовой PostgreSQL 17.6, штатный maintenance вернул job в очередь и учёл одно истечение. Интервал renewal оставался production **45 секунд**; часы и worker-функции не подменялись.

После фактического HTTP **404** на renewal тест передал job другому worker с новым lease и освободил модельный ответ. Исходный worker всё равно отправил **complete → 400**, затем **fail → 400**. БД уже защищала нового владельца, но клиент продолжал отправлять заведомо устаревшие сообщения и оставлял renewer до завершения вычисления. Baseline: **1 FAIL и 2 PASS** для прежних COMMIT-контролей.

Это согласуется с известным различием между временным сетевым отказом и утратой конкретной попытки: например, [Temporal описывает NOT_FOUND на heartbeat](https://docs.temporal.io/troubleshooting/request-failures#not_found-on-activity-heartbeat) как признак уже закрытой попытки, а поздний ответ не возвращает ей владение. Здесь используется собственный REST-контракт Агат и существующая классификация primary-renewer; Temporal SDK этим изменением не затрагивается.

## Изменение worker

`knowledge_lease_renewer` передаёт событие отмены исполняющей функции и прекращает свой цикл при **401 / 403 / 404 / 409**. Перед inference и после возврата результата `execute_knowledge_lease` проверяет событие. При его установке worker не отправляет complete; если модель вернула ошибку после утраты аренды, не отправляет fail. Штатный finally останавливает и присоединяет renewal thread.

Ошибки **0 / 408 / 429 / 500 / 502 / 503 / 504** не означают окончательной утраты lease: renewer продолжает цикл, а успешный inference может завершиться обычным complete. Ошибка самой модели при временном отказе renewal по-прежнему сообщается через fail. Координатор сохраняет все серверные проверки владельца и срока: отмена может прийти сразу после локальной проверки, поэтому клиентское событие не заменяет SQL-защиту.

## Проверки

Восемь целевых unit-тестов проверяют четыре окончательных и семь временных статусов, штатную остановку, совместимый вызов renewer без получателя cancellation, успешный/ошибочный inference после отказа и сохранение обработки ошибок при временном сбое. Контролируемое завершение модели синхронизируется с настоящей классификацией API-ошибки; join и завершение потока проверяются отдельно.

PostgreSQL-сценарий использует реальный Python worker, реальный model HTTP, обычный coordinator и исходный 45-секундный interval. После 404 ожидается выход renewer до снятия model barrier. Затем должны отсутствовать оба устаревших POST, снимок lease нового владельца сохраняется, а его успешный ответ записывает только новый вектор `[0,1]` и одно ready-событие. Законный счётчик единственного expiry остаётся **1**; дополнительных failures нет.

Первый прогон после исправления уже показал отсутствие устаревших POST, но выявил ошибку ожидания fixture: тест требовал failures=0 после намеренного expiry. Исправлено ожидание сохранения счётчика, установленного maintenance, без изменения runtime. Этот неудачный лог сохраняется отдельно от исходного контрпримера и итоговых проверок.

Целевые PostgreSQL-сценарии после исправления — **3/3 PASS**; при реальном renewal 404 устаревших terminal HTTP attempts — **0**. [Логи и SHA](./evidence/2026-09-27/embedding-worker-lease-cancellation/checks.json) сохраняют baseline, отдельную ошибку fixture и успешный повтор. Полный PostgreSQL-набор — **68/68**; typecheck, docs-check (12 Node / 165 Python) и architecture audit — pass. Worker unit suite: **52 PASS / 1 SKIP**, включая 8 новых тестов; штатный skip относится к неустановленной локально зависимости LangGraph.

```sh
python3 -m unittest discover -s workers -p test_embedding_cancellation.py -v
bash scripts/test-fleet-ha-postgres.sh --test-name-pattern='real Python embedding worker'
bash scripts/test-fleet-ha-postgres.sh
npm run test:worker
npm run typecheck
npm run docs:check
```

Отмена здесь кооперативная: она прекращает renewal и отправку устаревшего результата, но не прерывает уже выполняющийся блокирующий HTTP inference. Worker освобождает слот после возврата или штатной ошибки этого вызова. Тест использует контролируемый ответ модели, не нейронные веса; не доказывает отмену вычислений на backend или качество embedding. Следующий gate — ограниченное чтение успешного и ошибочного HTTP-ответа embedding endpoint с учётом контракта до 32 векторов по 4096 компонентов.

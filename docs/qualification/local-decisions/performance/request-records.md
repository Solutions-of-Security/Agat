# Расчёт по отдельным заявкам и проверка дублей

26.09.2026. Добавлен путь **закреплённый CSV заявок → проверка ключей и дублей → суммы по периодам → точная арифметика → отчёт с согласованием**. Он дополняет [адаптер двух агрегатных строк](./source-records.md). На авторском учебном примере шесть строк дают четыре уникальные пары «период + ID заявки»; два одинаковых повтора исключены из сумм с сохранением исходных строк в расчётном JSON.

[Подготовка новых снимков локального файла](./source-snapshots.md) сохраняет явные поля/периоды/единицы в рецепте, проверяет стабильность чтения и создаёт новый bundle с собственным SHA и сравнением с предыдущим. Прежние источники и результаты не перезаписываются.

## Контракт данных

[Mapping примера](./evidence/2026-09-26/request-records/mapping.json) имеет отдельную версию `agat.report.request-csv-mapping.v1`. Он явно задаёт SHA-256 всего источника, URI, включительные номера физических строк таблицы, четыре имени столбцов, два упорядоченных периода, единицы и совокупность. Порядок записей в CSV свободный; порядок сравнения задаётся только mapping.

| Поле | Значение |
|---|---|
| `requestId` | Непустой строковый ID до 64 символов: латинские буквы, цифры, `_` и `-`; первый символ — буква или цифра |
| `period` | Один из двух явно заданных периодов |
| `processingHours` | Неотрицательная десятичная строка, максимум шесть знаков после точки; единица — часы |
| `hasException` | Только `0` или `1`; признак заявки, а не число событий |

Каждая строка описывает **полную заявку за период**, включая все её часы. Mapping объявляет `recordScope: one_complete_request_per_period`, `hoursScope: same_counted_requests`, `exceptionScope: boolean_per_counted_request` и `comparablePeriods: true`. Эти объявления не устанавливают фактический смысл выгрузки. Для журнала событий или отдельных интервалов работы нужен иной расчёт.

Дедупликация требует точного объявления `key: ["period", "requestId"]`, `matching: typed_values`, `conflict: reject`. ID сравниваются посимвольно с учётом регистра: `001`, `1`, `A` и `a` различаются. Один ID в разных периодах учитывается отдельно. Для одинакового ключа часы сравниваются как точные дроби, а признак — как 0/1; `1` и `1.0` часа равны. При совпадении повтор исключается из сумм, но сохраняет `duplicateOf`, исходные ячейки, номера строк, byte offsets и SHA. При расхождении часов или признака весь расчёт отклоняется с номерами конфликтующих строк. Выбор первого/последнего значения или сложение конфликтов не выполняются.

В каждом периоде должна быть хотя бы одна запись: отсутствие периода не интерпретируется как ноль заявок. Неизвестные периоды, пустые поля, формулы, неоднозначные булевы значения, неверные заголовки, лишние столбцы и повреждённый CSV отклоняются. Значения не нормализуются и строки не фильтруются автоматически. Пустую совокупность можно задать явно в прежнем агрегатном контракте.

Лимиты адаптера: UTF-8, до 2 МиБ всего источника, до 20 000 физических строк и 10 000 записей данных. BOM и CRLF сохраняются. Сумма часов каждого периода не превышает 10¹². Все суммы и отношения вычисляются без binary float; округление применяется только для отображения.

## Запуск

```bash
python3 scripts/calculate-request-report.py \
  --source docs/qualification/local-decisions/performance/evidence/2026-09-26/request-records/source.csv \
  --mapping docs/qualification/local-decisions/performance/evidence/2026-09-26/request-records/mapping.json \
  --output docs/qualification/local-decisions/performance/evidence/new-request-report/result.json \
  --markdown docs/qualification/local-decisions/performance/evidence/new-request-report/report.md

python3 scripts/prepare-source-report-process.py \
  --source docs/qualification/local-decisions/performance/evidence/2026-09-26/request-records/source.csv \
  --mapping docs/qualification/local-decisions/performance/evidence/2026-09-26/request-records/mapping.json \
  --name 'Отчёт по отдельным заявкам' \
  --output docs/qualification/local-decisions/performance/evidence/new-request-process/bundle.json \
  --process-json docs/qualification/local-decisions/performance/evidence/new-request-process/process.json
```

[CLI расчёта](../../../../scripts/calculate-request-report.py) и [библиотека](../../../../scripts/lib/report_request_records.py) создают новые файлы под `docs`, не перезаписывая существующие. Проверка источника и расчёт происходят до записи выходных файлов. `request_markdown` заново разбирает источник и пересчитывает дубли и показатели; повторный внешний seal не позволяет принять изменённые числа или provenance.

Генератор процесса выбирает адаптер по точной версии mapping. [Подготовленный bundle](./evidence/2026-09-26/request-records/bundle.json) и [process JSON](./evidence/2026-09-26/request-records/process.json) используют прежний [путь согласования](./source-process.md): до подтверждения нет файлов; после — Markdown, исходный CSV и расчётный JSON; после отказа файлов нет. Сохраняется весь CSV, включая исключённые повторы. Лимит процесса — 100 000 символов literal JSON после экранирования, поэтому не вся выгрузка, допустимая offline-калькулятором, помещается в этот процесс. Превышение отклоняется без усечения.

## Проверка результата

[План](./evidence/2026-09-26/request-records/plan.json) закрепил исходник, mapping, ожидаемые суммы, девять точных величин и SHA кода до запуска CLI. В [результате](./evidence/2026-09-26/request-records/result.json): по две заявки в каждом периоде, часы 4 → 3, среднее 2 → 1,5 часа (−25%), доля признака 50% → 50% (0 п.п.). [Готовый Markdown](./evidence/2026-09-26/request-records/report.md) включает правила ключа, количество исключённых повторов и ограничения интерпретации.

11 новых Python-тестов проверяют конфликты в любом порядке, ведущие нули ID, одинаковый ID в разных периодах, точность дробей, BOM/CRLF и byte offsets, отсутствие/лишний период, строгие поля и декларации, границу 10 000 записей, подмену повторно запечатанных результатов и отказ CLI без выходных файлов. В 25 детерминированных наборах со случайным порядком и повторениями суммы сверены с отдельным целочисленным расчётом в миллионных долях часа. Вместе с прежней арифметикой, source binding и подготовкой процесса — **38/38 pass**.

Оба HTTP-сценария, агрегатный и по заявкам, прошли через настоящий временный coordinator/SQLite: публикация, обязательное согласование, запрет частичного старта, подменённый input, подтверждение/отклонение и скачивание трёх файлов с проверкой SHA. Это автоматическая проверка механизма на синтетических данных, не предметное согласование человеком.

[Независимая перепроверка](./evidence/2026-09-26/request-records/verification.json) сверила шесть исходных byte spans, две ссылки на исключённые повторы, все девять ожидаемых величин, Markdown и bundle. Прежний агрегатный bundle проверен с архивным генератором; его граф и три артефакта совпали с новой подготовкой. Desktop 1440×1000 и Pixel 7 412×839 прошли путь согласования и скачивания CSV через Playwright с установленным Chrome: **2/2 pass**, без ошибок console/pageerror, выхода заголовка за экран или изменения SHA. Просмотрены mobile-заголовок и согласование, desktop-артефакты; шесть скриншотов закреплены в verification. Полный `docs:check`: **12 Node- и 126 Python-тестов**, 1298 локальных ссылок в 150 Markdown-файлах и каталог 7 категорий / 13 шаблонов — pass. Coordinator typecheck также прошёл.

Пример создан специально для диагностики; это не новые независимые бизнес-данные и не qualification модели. Дедупликация проверяет объявленный ключ внутри выбранного диапазона. Она не доказывает уникальность ID в реальном мире, полноту выгрузки, достоверность, правильность единиц или сопоставимость совокупностей. Соответствующие flags остаются `false`.

## Основания решения

Использован [стандартный CSV reader Python](https://docs.python.org/3/library/csv.html): строки читаются с `newline=''`, значения не переводятся автоматически в float. [Документация PostgreSQL](https://www.postgresql.org/docs/current/ddl-constraints.html) описывает уникальность сочетания столбцов; здесь сочетание периода и ID выбрано явным контрактом задачи. [pandas `drop_duplicates`](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.drop_duplicates.html) позволяет задавать столбцы и оставлять первый/последний повтор. Для этого отчёта такой выбор при различных значениях скрыл бы конфликт, поэтому реализован отказ с сохранением номеров строк. pandas в зависимости проекта не добавлялся.

# Длина контекста, задержка и граница отказа

26.09.2026. Выполнены два отдельных процесса runtime 0.6.0 на Apple M1 Max, 32 ГиБ, с `Mapika/decider-2b`, cache 128 МиБ и явно заданными лимитами 2048/4096 токенов. Все 81 измеряемое вычисление завершилось; четыре запроса на один токен сверх соответствующего лимита вернули `context_too_long`. Это синтетический ресурсный опыт, без qualification качества или SLO.

## Вход и измерение

[Измеритель](../../../../scripts/profile-decision-context.py) не принимает dataset. Он строит запросы `agat.synthetic-context.v1`: одна запись «Контрольный код документа: АГАТ-42», вопрос о коде, три неизменных варианта и повторяющийся фон ` x`. Факт помещён в начало, середину и конец. Длина подбирается количеством повторов фона, затем проверяется закреплённым tokenizer с тем же раздельным кодированием state/question, что использует runtime. В число токенов входят wrapper, вопрос и описания вариантов. Ни текст, ни токены не обрезаются. Если точное число построить нельзя, опыт прекращается с ошибкой.

Первый процесс проверяет 256, 512, 1024, 2048 токенов; второй добавляет 4096. На каждую длину — три позиции факта и три повтора, то есть девять вычислений. Один прогрев выполнен только для самого короткого входа с фактом в начале. Первое вычисление каждой большей формы остаётся в измерениях. Порядок фиксирован: возрастание длины, начало → середина → конец, повторы подряд. Runtime для каждого запроса использует свежее состояние backbone.

До прогрева и после измерений выполняется запрос с фактом в конце и длиной `maxInputTokens + 1`. Ожидаемый отказ учитывается отдельно от распределения успешных задержек. Восемь unit checks включают вызов реального `MlxBackend.score` с подставным tokenizer и запретом любого обращения к GPU: oversized-вход отвергается до forward. Реальный прогон подтверждает отказ на закреплённом tokenizer, а точное совпадение `inputTokens` с планом — отсутствие скрытого усечения для разрешённых входов.

Снимки памяти снимаются после загрузки/построения входов, прогрева, каждой комбинации длины/позиции и последней проверки границы. Определения active, cache, peak и ограничений снимков совпадают с [ресурсным протоколом](./resources.md). HTTP, coordinator и primary-модель в измерение не входят; тестовые сервисы совместной нагрузки перед этим остановлены.

## Результат

| Длина, токенов | p50 / p95, мс, профиль 2048 | p50 / p95, мс, профиль 4096 |
|---:|---:|---:|
| 256 | 121.643 / 127.293 | 123.274 / 123.902 |
| 512 | 225.455 / 226.772 | 228.326 / 229.398 |
| 1024 | 436.262 / 444.591 | 433.001 / 437.224 |
| 2048 | 872.961 / 875.249 | 867.525 / 869.549 |
| 4096 | Не разрешено профилем | 1803.276 / 1942.878 |

При девяти измерениях p95 равен максимуму. Полные отчёты: [лимит 2048](./evidence/2026-09-26/decider-context-2048.json), [лимит 4096](./evidence/2026-09-26/decider-context-4096.json). Загрузка заняла 6042.093 и 4450.457 мс; системные файловые/shader caches не очищались. Оба отчёта имеют статус `observed`.

| Метрика | Профиль 2048 | Профиль 4096 |
|---|---:|---:|
| Peak active MLX, ГиБ | 4.254 | 4.426 |
| Максимум active+cache по снимкам, ГиБ | 3.640 | 3.640 |
| Запрос на один токен сверх лимита, до/после, мс | 2.060 / 2.019 | 3.681 / 5.829 |

Peak active выше суммы после запроса, поскольку активные временные буферы освобождаются до снимка. Лимит свободного cache 128 МиБ не ограничивает пик активных буферов. На этом опыте максимальная длина более чем удвоила время относительно 2048 токенов, при умеренном росте peak active. Это наблюдение для данной архитектуры и синтетического текста; оно не переносится автоматически на другую модель или production-нагрузку.

Модель во всех 81 вычислении выбрала `code_42`; пороги дали `ok`. Подписи распределений сохранялись на повторных одинаковых входах и совпали между профилями для общих длин. Это 15 уникальных синтетических входов с одним простым фактом; ни разнообразие документов, ни устойчивость к конфликтам/инструкциям, ни калибровка этими результатами не доказаны. Большое значение `selectedProbability` не является измеренной вероятностью истины.

[Независимая перепроверка](./evidence/2026-09-26/context-verification.json) подтвердила seals, hashes инструментов/входов, сохранность факта, точные counts, p95, maxima памяти и совпадение ответов. Профиль 4096 выбран только для опыта; default runtime остаётся 2048. Длинные входы увеличивают время сверх короткого shadow deadline, поэтому оператор должен выбирать лимит контекста вместе с deadline и проверять полный workload. Обещать production SLO по этим сериям нельзя.

## Воспроизведение

```bash
.venv/decision/bin/python scripts/profile-decision-context.py \
  --manifest .local-models/decisions/decider-2b.json \
  --max-tokens 2048 --rounds 3 --cache-limit-mib 128 --time-budget-s 120 \
  --output docs/qualification/local-decisions/performance/evidence/new-run/context-2048.json

python3 -m unittest scripts.test.test_decision_context -v
```

Для второго опыта укажите `--max-tokens 4096` и новый output. Загрузка идёт из существующего offline manifest; сеть и qualification datasets не используются. Полные синтетические запросы сохранены в отчёте для воспроизведения. Ограничения инструмента: до пяти длин, трёх позиций, пяти повторов, 75 измеряемых запросов и 300 секунд. Временной бюджет проверяется между вызовами и не прерывает активный Metal forward. Смена профиля/ответа, неправильный token count, неожиданный исход или неполный план дают `degraded`; ожидаемый отказ на превышение лимита — проверенный исход.

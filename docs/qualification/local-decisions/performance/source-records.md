# Расчёт по закреплённым CSV-записям с привязкой к источнику

26.09.2026. Добавлен путь **байты источника + явный mapping → проверенные ячейки → точная арифметика → Markdown**. На существующем учебном `SUPPORT-DEMO` подтверждены две исходные строки и девять контрольных величин: среднее 4 → 3 часа, −25%; доля 8% → 5%, −3 п.п. Это следующий шаг после [калькулятора структурированных записей](./arithmetic.md), которому раньше передавали готовые числа без проверки файла.

Следующий [подготовленный процесс с согласованием](./source-process.md) использует этот расчёт: показывает отчёт владельцу и после подтверждения сохраняет точные Markdown/CSV/JSON. Новые данные требуют новой подготовки; обычный модельный пакет v1 не меняется.

Для исходных строк отдельных заявок добавлен [отдельный адаптер с проверкой дублей](./request-records.md): ключ «период + ID», исключение одинаковых повторов и отказ при конфликте. Он использует собственную версию mapping; условия агрегатного формата ниже сохраняются.

[CLI](../../../../scripts/calculate-source-report.py) не вызывает модель и не меняет рабочие процессы. [Библиотека](../../../../scripts/lib/report_source_records.py) проверяет совпадение выбранных CSV-ячеек с исходными байтами, но не подтверждает истинность данных или правильность выбора совокупности. Для реального источника его владелец должен определить эти условия; они не выводятся из имён столбцов.

## Явный контракт

[Mapping](./evidence/2026-09-26/source-records-mapping.json) содержит версию `agat.report.csv-mapping.v1`, ID/URI источника, ожидаемый SHA-256, включительные номера первой и последней строки таблицы с 1, четыре имени столбцов и два периода в нужном порядке. Источник читается как UTF-8, поддерживаются BOM и CR/LF/CRLF. SHA вычисляется по исходным байтам, без нормализации перевода строк или кодировки. Размер — до 2 МиБ и 20 000 строк.

В выбранном диапазоне должны быть заголовок и ровно две полные четырёхколоночные записи. Порядок столбцов может отличаться, имена уникальны и точно совпадают с mapping. Кавычки CSV поддерживаются. Автоопределения диалекта, поиска «похожей» таблицы, удаления лишних строк и неявного восстановления пропусков нет. Пустые ячейки, повторные/переставленные периоды, неизвестные колонки, неверные границы и повреждённые кавычки приводят к отказу.

| Поле | Единица в контракте | Пример столбца `SUPPORT-DEMO` |
|---|---|---|
| `requests` | Число заявок | `requests` |
| `processingHours` | Часы для тех же заявок | `total_resolution_hours` |
| `exceptions` | Число заявок с признаком, максимум один раз на заявку | `reopened` |

Mapping обязан объявить `hoursScope: same_counted_requests`, `exceptionScope: at_most_one_per_counted_request`, `comparablePeriods: true` и ID совокупности. Минуты не превращаются в часы автоматически; число событий повторного открытия не принимается как число уникальных заявок с повторным открытием. Если источник считает события с возможными повторами, этот контракт не подходит: сначала нужен отдельный проверяемый расчёт по исходным записям. Проверка JSON-деклараций сама по себе не доказывает их соответствие реальному источнику.

В примере эти условия — **авторские диагностические допущения**. Существующая агрегатная таблица не даёт независимо проверить устранение повторов по заявкам. Человеческого согласования или предметной приёмки этим примером не заявлено.

Числа используют ограничения прежнего калькулятора: целые неотрицательные counts, десятичные строки часов, пределы значений и числа отклонений. Формулы, exponent notation, float-counts, локальная десятичная запятая и NaN отклоняются. Нулевой знаменатель остаётся неопределённым. В расчёте используются точные дроби; display округляется отдельно.

## Что сохраняется и перепроверяется

[Результат](./evidence/2026-09-26/source-records-result.json) содержит mapping, SHA файла и выбранной таблицы, исходные строки, их номера, полуоткрытые byte ranges `[start, end)`, SHA каждой строки и сопоставление ячеек. Рядом находится вход и результат точного калькулятора. `sourceBytesMatched` и `cellsMatchSelectedCsv` означают только проверенное соответствие байтам. `sourceTruthVerified`, `populationAlignmentVerified`, `qualifiedForRouting` и `routingEnabled` остаются `false`.

Перед созданием Markdown повторно проверяется весь результат по исходному файлу и выполняется расчёт. Подмена ячеек, offsets или вычисленных значений отвергается даже после пересчёта внешнего SHA. Перестановка ключей JSON не меняет Markdown. Hash обеспечивает проверку целостности; он не удостоверяет автора или достоверность файла.

[Отчёт](./evidence/2026-09-26/source-records-report.md) сохраняет связь с URI, SHA, строками и колонками. Название «отклонения» в общей таблице явно связано с выбранным столбцом `reopened` и условиями mapping. Готовые значения не передаются генеративной модели для переписывания в этом пути.

После исполнения независимо сверены байтовые границы обеих строк, все ячейки известного шаблона, привязка входа калькулятора, точные значения и отображение. Вместе с 11 арифметическими тестами — 22/22 pass.

[Общая проверка](./evidence/2026-09-26/source-records-checks.json): 12 Node- и 110 Python-тестов документации, 1240 локальных ссылок в 144 Markdown-файлах и каталог процессов — pass; SHA закреплённого кода повторно сверены.

```bash
python3 scripts/calculate-source-report.py \
  --source docs/qualification/local-decisions/performance/evidence/2026-09-26/source-records-source.csv \
  --mapping docs/qualification/local-decisions/performance/evidence/2026-09-26/source-records-mapping.json \

  --markdown docs/qualification/local-decisions/performance/evidence/new-source-run/report.md

  --fixture docs/qualification/internal-report/fixtures/sources.json \
  --evidence-dir docs/qualification/local-decisions/performance/evidence/new-source-probe
```

Output-пути должны быть новыми и находиться под `docs`. Ошибка source SHA/структуры обнаруживается до создания отчётных файлов. Производственный manifest пакета, маршруты, его обязательное решение человека и runtime модели 0.12.0 не менялись. Остаются реальные источники, проверка совокупности и полноты, дедупликация по ID при необходимости и подключение этого расчёта к прикладному процессу.

Разбор использует [стандартный Python CSV reader](https://docs.python.org/3/library/csv.html) с сохранением переводов строк и строковых значений; не используется эвристический `Sniffer`. Формат CSV и кавычек описан в [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180). Ограничения на поля, количество записей и декларации — контракт этого адаптера.

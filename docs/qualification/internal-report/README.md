# Квалификация пакета «Внутренний отчёт» на реальной инфраструктуре

Команда `npm run qualify:internal-report` проверяет установленный пакет целиком: настоящий локальный Qwen3 → настоящие embeddings → retrieval → три агента → согласование → скачивание отчёта. Процессом управляет настоящий Temporal Server. Gate завершается успешно только после всех обязательных проверок, включая восстановление после аварии. Отсутствие модели, embeddings, Temporal или зависимостей — **FAIL, код 2**, без пропуска и без перехода на встроенный runtime.

Точка входа: [qualify-internal-report.mjs](../../../scripts/qualify-internal-report.mjs). Команду запускают из корня репозитория. Результаты каждого запуска — отдельная новая директория с `result.json` и русским `result.md` под `/docs/qualification/internal-report/evidence`. [Зафиксированные результаты](./results.md) отделяют реально выполненные проверки от ограничений.

## Подготовка

Нужны Node.js согласно `.nvmrc` (24), npm, Git, Python 3.13+ и локальный Ollama. Обычный Python worker `single/tool_loop_v1` при выключенной телеметрии использует стандартную библиотеку; установка LangGraph и OpenTelemetry для этого сценария не требуется. Зависимости JavaScript устанавливаются строго из lock-файла:

```sh
npm ci
ollama --version
# Если Ollama ещё не запущен, в отдельном терминале:
ollama serve
```

В работающий локальный Ollama загрузите модели. Требуется место для весов и оперативная память для Qwen3 8B и embeddings; загрузка Qwen3 занимает несколько гигабайт.

```sh
ollama pull qwen3:8b
ollama pull embeddinggemma
```

Оба API (`/v1/chat/completions` и `/v1/embeddings`) обслуживает этот экземпляр Ollama. Gate проверяет наличие модели через `/api/tags`, архитектуру и capability через `/api/show`, версию через `/api/version`, а затем действительно вычисляет embedding. Модель с одним подходящим именем, но другой архитектурой или облачным `remote_host`, не проходит проверку. Qwen3.5 и Qwen3.6 не подменяют квалификацию Qwen3.

Изолированный Temporal можно поднять поставляемой конфигурацией:

```sh
docker compose -p agat-report-qualification \
  -f docs/qualification/internal-report/compose.yaml up -d --wait
```

В [compose.yaml](./compose.yaml) образ CLI закреплён digest, порт 7233 опубликован только на `127.0.0.1`; namespace — `default`. Версия CLI/образа отличается от версии встроенного Temporal Server: gate записывает именно `GetSystemInfo.serverVersion`. Данные стенда хранятся внутри контейнера. Другой вариант — установленный Temporal CLI в отдельном терминале:

```sh
temporal server start-dev --ip 127.0.0.1 --port 7233 --headless
```

Если порт уже занят вашим локальным Temporal, используйте существующий namespace или задайте другой локальный адрес. Gate создаёт уникальную очередь и уникальный workflow; он не останавливает чужие worker и серверы. Сервис Temporal и модели должны быть подготовлены **до** запуска gate: сама проверка ничего не скачивает и не создаёт отсутствующую инфраструктуру.

## Запуск и критерий завершения

```sh
npm run test:qualification
npm run qualify:internal-report
```

Первая команда проверяет сам gate на синтетических unit fixtures и недоступных адресах. Она входит в `npm run docs:check` и обычный CI. Её успех не означает квалификацию модели. Вторая команда выполняет реальный сценарий; в ней нет флагов `skip`, `dry-run` и подмены worker. Установленный Temporal SDK должен совпадать с `package-lock.json` для всех шести используемых пакетов. Затем gate собирает coordinator и production workflow bundle.

| Код выхода | Значение |
|---|---|
| `0` | Все обязательные проверки имеют `PASS` |
| `1` | Ошибка сценария, содержимого, цитат, восстановления, очистки или записи результата |
| `2` | Не выполнены требования к конфигурации/инфраструктуре, включая отсутствующие модели и namespace |

`NOT_RUN` — обязательная проверка не выполнялась вследствие предыдущей ошибки. Такой результат всегда `FAIL`. Непустую директорию результата нельзя использовать повторно; старый `PASS` не перезаписывается новым запуском. Для повторного запуска укажите новое имя или используйте автоматически создаваемое.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AGAT_QUALIFICATION_MODEL` | `qwen3:8b` | Точное имя локального Qwen3; другой размер — отдельный результат |
| `AGAT_QUALIFICATION_OLLAMA_URL` | `http://127.0.0.1:11434` | Корень локального Ollama, без `/v1`, credentials и query |
| `AGAT_QUALIFICATION_TEMPORAL_ADDRESS` | `127.0.0.1:7233` | Локальный gRPC endpoint |
| `AGAT_QUALIFICATION_NAMESPACE` | `default` | Существующий namespace |
| `AGAT_QUALIFICATION_TIMEOUT_SECONDS` | `1800` | Общий бюджет ожидания готовности и генерации; от 60 до 7200 секунд |
| `AGAT_QUALIFICATION_OUTPUT` | `docs/qualification/internal-report/evidence/local-…` | Новая директория результата внутри `/docs` |
| `AGAT_QUALIFICATION_QWEN_SHA256` | Не задана | Ожидаемый digest Qwen3 из предыдущего результата |
| `AGAT_QUALIFICATION_EMBEDDING_SHA256` | Не задана | Ожидаемый digest embeddinggemma из предыдущего результата |

Принимаются только IP loopback `127.0.0.1` / `[::1]`, HTTP для Ollama и `host:port` для Temporal. DNS-имена и редиректы запрещены. Embedding-модель пакета — `embeddinggemma`; заменить её переменной окружения нельзя. Для воспроизведения конкретного результата укажите оба записанных digest: изменившийся тег тогда даст `MODEL_DIGEST_MISMATCH`.

## Что считается доказательством

| Проверка | Обязательные наблюдения |
|---|---|
| Версии и входные данные | Node/Python/OS/архитектура, версии Temporal SDK и Server, Ollama и coordinator; digest/семейство/квантизация моделей; commit, dirty flag, SHA-256 исходников и lock-файла, хеш workflow bundle |
| Установка | Настоящие HTTP API, идемпотентный повтор, закреплённые manifest/process version; `409` при попытке старта до подключения model worker |
| Ingestion | Оба документа совпадают с [безопасной fixture](./fixtures/sources.json), имеют статус `ready`; хеши всех фрагментов и одинаковая ненулевая размерность настоящих embeddings |
| Retrieval и цитаты | Каждый из трёх агентных этапов действительно вызывал Qwen3; обе исходные записи найдены, цитируются и связываются с URI, хешем документа и хешем фрагмента; неизвестный `[K…]` запрещён; запросы имеют только хеш вектора и размерность |
| Содержание | Июль/август, 100/120 заявок (+20%), `400/100=4`, `360/120=3` (−25%), `8/100=8%`, `6/120=5%` (−3 п.п.), учебный характер данных и невозможность установить причины |
| Approval | Состояние `waiting_approval`, итоговых артефактов ещё нет; посторонний токен получает `401`; обход согласования через partial start получает `400` |
| Восстановление | `SIGKILL` принадлежащих сценарию coordinator и Temporal worker в ожидании согласования; сохранённый запрос переживает рестарт coordinator; до решения артефакта нет; решение принимается при остановленном worker, Temporal остаётся `RUNNING`; новый worker заканчивает **тот же** Temporal run |
| Скачивание | Ровно один `internal-report.md`, `401` без авторизации, `200` с ней, attachment-заголовок, размер и SHA-256 равны Artifact Store; байты содержат именно согласованный вывод проверяющего |
| Temporal history | Workflow завершён, в истории есть завершённые workflow tasks от двух собственных worker identities; хеши агентных результатов и количество retrieval не изменились при восстановлении |
| Стабильность и очистка | Digest моделей и входные файлы не изменились за время прогона; собственные процессы завершены, временная БД, credentials и артефакты удалены |

Согласование в этом тесте — автоматическое действие отдельного технического администратора **только над синтетическими данными**, после прохождения машинного рубрикатора. В evidence явно записаны `approvalActor=automated-synthetic-qualification` и `humanReview=false`. Это проверка механизма согласования, а не подпись владельца настоящего отчёта.

Если рубрикатор не пройден, текущий harness отправляет `reject`, проверяет `cancelled` и отсутствие итогового файла, затем всё равно возвращает `FAIL`. Положительное согласование и восстановление при этом остаются непроверенными. Для ingestion отдельно сохраняются хеш исходной fixture и хеш документа после стандартной нормализации перевода строк и обрезки внешних пробелов; у CSV они отличаются из-за завершающего перевода строки.

Квалификационное задание состоит из `manifest.sample.input` и фиксированного `inputSuffix` в [fixture](./fixtures/sources.json). Дополнение явно требует относительных процентов, изменения доли в процентных пунктах и формул в простом тексте. Оно **не содержит эталонных ответов**. Evidence сохраняет SHA-256 всего задания. Установленные граф, агенты, источники и их инструкции не изменяются. Результат относится к этому фиксированному заданию, а не ко всем возможным вопросам или к исходному короткому примеру без дополнения.

Машинный рубрикатор проверяет ограниченный набор чисел и формулировок. Корректная, но иная запись формул может дать `REPORT_RUBRIC_FAILED`; без анализа нельзя ослаблять критерии ради зелёного результата. Рубрикатор не доказывает истинность произвольного текста и не заменяет экспертную оценку. Температура рабочего model client — 0.2; LLM недетерминирована, поэтому повторяем критерии и provenance, а не обещаем идентичные байты текста.

В текущей архитектуре АГАТ coordinator синхронно выполняет переходы графа, включая сохранение артефакта после принятого решения. Temporal фиксирует жизненный цикл через activities/updates и управляет долговременными ожиданиями. Поэтому после `approve` артефакт может появиться при остановленном Temporal worker; gate требует, чтобы именно Temporal workflow завершился после восстановления и сохранил прежний run ID. До остановки worker отдельно проверяется `processState=waiting_approval` через Temporal query.

Сценарий восстанавливает coordinator и Temporal worker на стадии согласования. Он не квалифицирует потерю Temporal Server, сбой диска, PostgreSQL, сбой GPU во время генерации, интерфейс браузера или производственный HA. Эти границы нельзя расширять на основании одного `PASS`.

## Безопасность доказательств и очистка

Все постоянные файлы — whitelist-проекции с фиксированными кодами ошибок. Полный отчёт подтверждается хешем и рубрикой, но его текст не копируется в evidence. Для диагностики рубрики допускается ограниченный список числовых значений с `%`, без окружающего текста. Не сохраняются токены, заголовки запросов, путь к домашнему каталогу, полные API responses, reasoning, embedding vectors, raw Temporal history, stack traces или журналы subprocess. Сами документы — только два синтетических источника из manifest.

Gate передаёт дочерним процессам минимальный набор переменных среды, генерирует отдельные токены и создаёт временное состояние с правами `0700`. Обычная ошибка, таймаут и обрабатываемый сигнал приводят к очистке. Принудительное убийство самого harness через `SIGKILL` или выключение машины не позволяют выполнить `finally`: оператору нужно удалить только оставшийся каталог `agat-report-qualification-*` из системного temporary directory и завершить только процессы этого прогона. Не прикладывайте оставшиеся БД/credentials к issue или CI artifact.

Локальные автоматические evidence-каталоги `local-*` исключены из Git. Для фиксации результата задайте новое явное имя, проверьте `result.json` и добавьте только безопасные `result.json` / `result.md`. После работы остановите отдельный Temporal:

```sh
docker compose -p agat-report-qualification \
  -f docs/qualification/internal-report/compose.yaml down
```

Удаление контейнера удаляет его временную историю. Модели остаются в локальном Ollama для следующего прогона. Внешний уже работавший Temporal этим способом останавливать не нужно.

## Автоматизация и разбор ошибок

[Workflow GitHub Actions](../../../.github/workflows/internal-report-qualification.yml) запускается вручную на доверенном runner с labels `self-hosted, agat-qualification`, подготовленными Ollama/моделями/Temporal. Он публикует только `result.*` даже при `FAIL`; отсутствие этих файлов тоже является ошибкой. Автоматического запуска непроверенного PR-кода на таком runner нет. При отсутствии runner задание останется в очереди и не подтвердит квалификацию. Для release gate требуйте успешный job именно для выпускаемого commit и сопоставляйте `result.inputs` с ним.

| Код | Действие |
|---|---|
| `SDK_LOCK_MISMATCH`, `DEPENDENCIES_UNAVAILABLE` | Выполнить `npm ci`, проверить Node/Python |
| `OLLAMA_UNAVAILABLE` | Проверить локальный endpoint и `ollama serve` |
| `MODEL_NOT_INSTALLED`, `EMBEDDING_MODEL_UNAVAILABLE` | Загрузить точную модель; одного названия в настройках worker недостаточно |
| `MODEL_DIGEST_MISMATCH` | Восстановить закреплённые веса либо оформить новый квалификационный результат |
| `TEMPORAL_UNAVAILABLE` | Проверить gRPC порт, health и существование namespace |
| `TEMPORAL_POLLER_MISSING`, `OWNED_PROCESS_EXITED` | Проверить совместимость Node и установленного native Temporal SDK; повторить сборку отдельно |
| `INGESTION_TIMEOUT`, `GENERATION_TIMEOUT` | Проверить ресурсы модели и доступность сервисов; новый прогон после устранения причины |
| `REQUIRED_SOURCE_NOT_CITED`, `CITATION_UNKNOWN_OR_MISSING`, `REPORT_RUBRIC_FAILED` | Качество Qwen3 не прошло критерии; проверить критерии и исходную конфигурацию, не считать запуск успешным |
| `RECOVERY_TIMEOUT`, `WORKFLOW_REPLACED`, `DOWNLOAD_CONTENT_MISMATCH` | Ошибка runtime/артефактов: квалификация не пройдена |

Контракты внешних сервисов: [Ollama list models](https://docs.ollama.com/api/tags), [Temporal CLI start-dev](https://docs.temporal.io/cli/command-reference/server). В последнем описаны локальный сервер, привязка порта и хранение истории; production-развёртывание в этот сценарий не входит.

# Agat 1.7.0 — public preview

Первая версионированная публичная поставка. GitHub release помечен как **prerelease**.
Версия предназначена для локального знакомства и проверки сценариев в своём контуре.
Production qualification конкретного развёртывания и полные solution packs остаются
отдельными задачами [roadmap](../roadmap.md).

## Возможности

- Локальные AI-агенты, распределённые Python workers и OpenAI-compatible model servers.
- Визуальные процессы, 13 шаблонов, условия, циклы и согласования.
- Журнал выполнения, результаты, replay/eval и артефакты.
- Local RAG, MCP и A2A при настройке источников и разрешений.
- SQLite по умолчанию; отдельные профили PostgreSQL и Temporal.

Публичный вход включает [первый сценарий](../first-run.md), [Docker-руководство](../local-docker.md),
[English README](../README.en.md), правила участия и приватное сообщение об уязвимости.

## Установка

Используйте tag `v1.7.0` и команды из [README](../README.md#быстрый-запуск).
Рекомендуется Node.js 24; CI использует Python 3.13. Заявленные минимумы — Node.js 22.13,
Python 3.10. Для обычного `single` worker Python-зависимости не обязательны;
LangGraph и OpenTelemetry требуют `workers/requirements.txt`.

## Проверки и ограничения

Актуальный результат проверки привязан к SHA в [GitHub Actions](https://github.com/Solutions-of-Security/Agat/actions/workflows/ci.yml).
Check `required` объединяет typecheck/unit/build, проверку документации,
desktop/mobile Chromium smoke и четыре набора PostgreSQL/S3 интеграций.
Браузерный worker работает в `--dry-run`: это проверка UI/API/persistence, не качества LLM.
Temporal history replay не заменяет проверку работающего Temporal server.

Локальный SQLite поддерживает один coordinator. HA, managed PostgreSQL, S3 retention,
OIDC, mobile attestation и region-loss recovery требуют операторской настройки и
проверки реального контура. Каталог процессов предоставляет схемы и роли; доменные
коннекторы, права, eval и готовность каждого сценария проверяются отдельно.

## Обновление с раннего публичного snapshot

1. Остановите coordinator и workers. Сделайте согласованную резервную копию SQLite
   и каталога артефактов либо backup используемого PostgreSQL/S3-контура.
2. Сохраните локальный `.env` и параметры путей. `setup-local-env.py` не заменяет существующий файл.
3. Проверьте чистоту своего checkout, выберите tag `v1.7.0`, выполните `npm ci` и `npm run build`.
4. Для PostgreSQL сначала следуйте [руководству миграции схемы](../postgresql-migration-job-runtime-role.md);
   не выдавайте runtime-пользователю DDL-права. SQLite мигрируется coordinator при старте.
5. Запустите сервисы; проверьте `/api/v1/health`, подключение worker и [первый сценарий](../first-run.md).

Для отката используйте согласованную копию данных и прежнюю версию приложения;
запуск старого бинарного файла на изменённой схеме не является подтверждённым rollback.
Новые функции незавершённых веток 1.8/1.9 в этот release не заявлены.

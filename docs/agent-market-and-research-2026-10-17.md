# Агат: рынок агентных продуктов и исследования

Дата среза: **17 октября 2026 года**, Europe/Moscow. Назначение: скорректировать развитие Агата и подготовить исполнимый backlog. Актуальный порядок поставки — в [roadmap](./roadmap.md), новые карточки — в [backlog](./agent-evolution-backlog-2026-10-17.md), архитектурное предложение — в [ADR-022](./adr-022-evidence-led-agent-evolution.md).

## Вывод

Агату целесообразно развивать законченный путь **«свои материалы → проверенный отчёт → решение человека → повторная задача»**. Его основа уже существует. Следующий результат должен объединить установку, документы, проверку содержания и понятную приёмку. Локальное исполнение, ограничения передачи данных и восстановление процесса образуют перспективное позиционирование; их преимущество по стоимости и качеству ещё нужно измерить.

Рынок уже предлагает визуальные workflows, human-in-the-loop, память и evals. Поэтому наличие этих механизмов само по себе не подтверждает конкурентное преимущество. Исследования поддерживают выбор архитектуры по задаче, проверку конечного состояния, повторные испытания, управление контекстом и контролируемую память. Рекомендуется:

1. Уточнить остаток работ по существующим PDF/DOCX и пакету `internal-report`, сохранив имеющуюся реализацию и evidence.
2. Перенести минимальную проверку результата и ограничение контекста в P0; расширенную самокритику и загрузку skills оставить отдельными экспериментами.
3. Сравнить workflow с одним агентом, фиксированную цепочку и specialist team. Закреплять профиль pack по измерениям, сохраняя простой baseline.
4. Добавить проверку агентных траекторий, регрессии из ошибок, управляемую память, контракты делегации и вмешательство человека во время работы.
5. Сохранить OpenRouter первым планируемым inference-подключением. Полный UX внешнего A2A-исполнителя перенести в P1: он не должен задерживать первый отчёт. Сам существующий A2A adapter сохраняется.

## Границы и метод

**AS-IS:** package version `1.7.0`, локальная ссылка HEAD `78d4cfba1387cf41f59c2965cefbaec3f0c3820e`, выбранные файлы текущего workspace. Рабочие изменения присутствуют; публичный релиз и рабочая копия различаются. Полный `git status` не завершился за время первичной инвентаризации из-за подгрузки файлов. Срез установленных сервисов и production telemetry не собирался.

Разрешённое действие — исследование и изменение проектной документации. Программный код, настройки развёртывания и внешние трекеры в этой работе не меняются. Аудит уязвимостей, закупка, платные API-вызовы, установка конкурентов и сравнительные прогоны не входят в выполненную работу.

Проверены официальные документы восьми продуктовых предложений и девять исследовательских работ. Поиск охватывал orchestration, evaluation, reliability, memory, skills и long-horizon research, включая публикации сентября–октября 2026. Это целевая выборка для Агата, а не систематический обзор всех публикаций. Для научных источников сверены страницы авторских публикаций и версии; для scaling, memory, memory injection, skill use и rater drift дополнительно просмотрены HTML полных текстов. Остальные выводы ограничены содержанием abstracts. Численные результаты исследований не переносятся на Агат.

Уровни доказательств: **OBS** — прочитанный код; **DOC** — документация или прежний протокол; **EXT** — внешний первичный источник; **INF** — рекомендация на их основе; **TBD** — требуется дополнительное evidence. Высокая уверенность относится к найденным механизмам и текстам контрактов, ограниченная — к реальному качеству, UX, экономике и readiness установок.

## Целевое развитие и варианты

| Вариант | Польза и цена | Решение |
| --- | --- | --- |
| Продолжать текущую фиксированную цепочку | Минимум изменений, уже есть узкое evidence; сохраняются неустановленная цена координации и пробелы общего сценария | Контрольный baseline, пригоден для ограниченной квалифицированной задачи |
| Законченное решение с измеряемым профилем исполнения | Переиспользует текущие механизмы, добавляет проверки и feedback. Требует корпуса и участия владельца процесса | Рекомендуемый ближайший TO-BE |
| Широкая multi-agent платформа, новые runtime/marketplace до пилота | Больше способов сборки; выше стоимость поддержки, scopes и координации без измеренного спроса | Стратегическая опция после результата EVAL-103 и повторного спроса |
| Внешний managed runtime как основа | Сокращает часть собственной runtime-разработки; добавляет зависимость от vendor, хранения и доступности | Отдельный P1 adapter только по конкретному сценарию; не заменяет текущий authority plane |

**Release TO-BE:** ограниченный report pack с подтверждёнными входами, проверкой результата, явным human decision, безопасной отменой и воспроизводимым eval. Для выбранного local/cloud профиля сохраняются model/prompt/tools/corpus/policy versions. **Strategic TO-BE:** долгие управляемые sessions, проверяемая делегация, корректируемая память, online quality loop и дополнительные packs по спросу.

Temporal/coordinator остаются владельцами durable процесса; model output, retrieved context, memory и peer output не выдают полномочия. Timeout, partial и unknown outcome не превращаются в успех. Имеющиеся authorization, data policy, approval, quotas и audit применяются и к новым профилям. Откат переключает только новые запуски на прежнюю версию; активные выполняются по закреплённому контракту либо явно останавливаются.

## Приёмка и экономика

Для EVAL-101 предлагается начальный корпус из 40 согласованных случаев: 20 development и 20 закрытых holdout, с источниками, числами, конфликтами, недостатком данных и отказами зависимостей. Каждый проверяемый профиль проходит минимум три trials на каждом случае; task ID, trial ID и exact configuration сохраняются. Это стартовый инженерный gate, а не оценка редких production-рисков.

Измеряются отдельно: успешное конечное состояние, принятие без существенной правки, ошибки claims/чисел/ссылок, корректный отказ/передача человеку, forbidden effects, доля всех трёх успешных trials, p50/p95 времени, повторы, труд человека и стоимость принятого результата. Confidence intervals для сравнений строятся по task clusters; trials одной задачи не выдаются за независимые пользовательские задачи. Неуспехи остаются в знаменателе.

Стоимость принятого результата = все измеренные затраты модели/tools/повторов и учтённой инфраструктуры, делённые на число принятых результатов. При нуле принятых значение не определено; unknown cost не считается нулём. Человеческое время показывается отдельно; его денежная оценка требует согласованной ставки. Локальная модель не означает нулевой стоимости, цена токена не равна цене результата.

Предлагаемый критерий выбора сложного профиля: нет ухудшения обязательных quality/safety gates и есть воспроизводимый выигрыш принятия либо не менее 20% сокращения затрат или труда при том же качестве. Порог 20% — продуктовая гипотеза, не результат исследования. До испытания владелец процесса фиксирует главный критерий и допустимую quality margin; если выборка не позволяет подтвердить эффект, сохраняется простой профиль и планируется отдельное расширение выборки. Никакой автоматической смены профиля по этому документу не происходит.

## Переход и проверка результата исследования

Последовательность: актуальный AS-IS и corpus → минимальный pack/контракты → выбранный local или cloud путь → проверенный отчёт → человеческий пилот → P1 расширение. Local и cloud квалифицируются независимо; внешний A2A performer, долгие sessions и новые бизнес-домены не блокируют первый local pilot. Production Fleet/DR gates остаются обязательными для соответствующего развёртывания.

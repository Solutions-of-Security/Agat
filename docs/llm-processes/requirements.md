# Требования к категориям и процессам с LLM-агентами

Версия 1, 11.09.2026. Статус: проект требований и локальная реализация каталога; не утверждённый допуск бизнес-процессов в production. Применение: все 13 процессов [каталога](./catalog.md) и новые процессы из [шаблона паспорта](./templates/process-passport.md).

Требования категории наследуются процессом. Предметные критерии перечислены в паспортах (`<template-id>/AC-1`, `AC-2`). Численные пороги бизнес-качества, SLA и затрат не заданы без владельца и данных: их необходимо заполнить до пилота. «Реализовано» ниже означает наличие механизма в этой поставке или существующем коде, а не автоматическое выполнение всей бизнес-политики.

## Контракт процесса

| ID | Требование | Приёмка | Состояние |
|---|---|---|---|
| PRC-01 | Паспорт содержит цель, границы, триггер, вход, выход, этапы, роли, исключения и критерии | Все поля заполнены; вход и выход проверяемы владельцем | Паспорта 13 процессов в каталоге |
| PRC-02 | Одна основная категория по конечному результату; домен и оркестрация описываются отдельно | Все template.categoryId ссылаются на существующую категорию | Реализовано и проверяется тестом |
| PRC-03 | Владелец определяет обязательность, типы, ограничения входа и результата | Отсутствующие/невалидные поля приводят к отказу или ручной проверке | Вход/результат описаны; доменные JSON Schema и валидаторы — перед интеграцией |
| PRC-04 | Каждый LLM-этап имеет конкретное задание, разрешённый контекст и контракт выхода | Вход и предыдущий результат доходят до следующего задания; результат не теряет evidence | Задания встроены в transform; содержательная сохранность проверяется review/eval |
| PRC-05 | Нельзя подменять неизвестный исход успехом | Пропуск, противоречие, недоступный источник и непроведённая проверка видны человеку | Инструкции + обязательное решение человека; не автоматическая проверка истинности |
| PRC-06 | Формулы, полномочия и машинные схемы проверяются детерминированно | Ошибка формулы/ACL/schema не обходится текстом агента | ACL/graph validation есть; предметные валидаторы настраиваются отдельно |
| PRC-07 | Финальное сохранение материала требует решения ответственного | До approval нет process artifact; reject прекращает процесс | Узел approval перед artifact во всех шаблонах |
| PRC-08 | Техническое завершение и принятие бизнес-результата различаются | В отчёте пилота отдельно completed, принятый материал, выполненная внешняя операция | Семантика описана; автоматического business outcome accounting здесь нет |
| PRC-09 | Повторное применение использует независимую копию определения | Изменение копии не меняет источник/другую копию | Реализовано: отдельный draft и последующие версии |
| PRC-10 | Процесс можно отменить; ошибку и отказ нельзя выдать за успех | Cancel/failure прекращают текущий путь; восстановление следует runtime-контракту | Используется существующий runtime, отдельные пользовательские испытания до пилота |

## Полномочия, данные и исполнение

Уровни ниже — обозначения паспорта процесса, не поля runtime и не новые роли доступа.

| Уровень | Агент может | Решение человека / детерминированного механизма |
|---|---|---|
| A0 — помощь | Объяснять материал по предоставленным данным | Человек выполняет весь процесс |
| A1 — подготовка | Исследовать разрешённые источники, предложить материал, проверить его | Человек принимает результат; профиль всех встроенных шаблонов |
| A2 — ограниченное исполнение | Предложить и вызвать заранее разрешённое действие | Policy проверяет субъект/объект/условия; согласование там, где оно требуется |
| A3 — автономность в заданных пределах | Действовать без решения человека на каждый шаг в заранее допущенной области | Точные бюджеты, детерминированные запреты, мониторинг и остановка; только после eval/допуска |

| ID | Обязательное правило перед эксплуатацией | Evidence |
|---|---|---|
| CTRL-01 | Права проверяются за пределами LLM; prompt и согласование артефакта не ограничивают tools сами по себе | Проверенный allowlist агента, запрет неразрешённого вызова, scoped credential |
| CTRL-02 | Внешняя запись отделена от подготовки: точные параметры, субъект, ресурс, полномочия, preview и разрешённый класс действия | Контракт интеграции и тест изменения/отказа; во встроенных схемах внешних write-узлов нет |
| CTRL-03 | Повтор после timeout записи требует сверки состояния; idempotency поддерживается принимающей системой | Дубли, потеря ответа, поздний callback и повтор после restart проверены на реальной интеграции |
| CTRL-04 | Для обратимой операции известен возврат, для необратимой — граница подтверждения | Испытание компенсации или ручной процедуры, владелец результата |
| CTRL-05 | Источники имеют владельца, версию/дату и границы доступа; секреты не входят в prompt, каталог, примеры и telemetry | Реестр источников/ACL, redaction, retention и удаление |
| CTRL-06 | Агент не назначает самому себе полномочия; policy, credentials и пороги допуска нельзя изменить входным текстом | Negative/adversarial case; ограничения в gateway/runtime |
| CTRL-07 | Контент источников и результаты агентов считаются данными; для HTML/SQL/shell/API применяются соответствующие валидаторы | Попытка инъекции не вызывает запрещённое действие; вывод не исполняется как код |
| CTRL-08 | Циклы, tools и retries ограничены; исчерпание лимита приводит к явному исходу | Заданные maxIterations/maxHandoffs, deadline, предел tool calls и затрат для выбранного профиля |
| CTRL-09 | Для экземпляра известны версии процесса, агентов/prompts, модели, tools/policy, источников и eval | Trace и release evidence; факт наличия версии в реестре не доказывает её deployment |
| CTRL-10 | Назначены владелец процесса, владелец данных, администратор policy, оператор и ответственный за инцидент | Заполненный паспорт; роль из шаблона заменена конкретным назначением до пилота |

Во встроенных схемах три LLM-этапа: два предметных и review. Это конечная последовательность; циклы/ветвления не включены. Число inference/tool calls внутри выбранного агента зависит от его runtime, а не от количества узлов. Записи в собственное хранилище артефактов Agat выполняет coordinator после решения человека. MCP/tool-права выбранных агентов нужно проверять отдельно.

## Исключения и состояния

| Ситуация | Требуемый исход | Текущее поведение шаблонов |
|---|---|---|
| Нет данных или evidence противоречит | Перечень пробелов; при невозможности приёмки — отказ/эскалация | Агент готовит исключения; человек решает на approval |
| Невалидное назначение агента | Отказ до создания | Серверная проверка проекта/ID |
| Агент не назначен | Сохранённый draft, publication blocked | Backend и UI readiness |
| Ошибка worker/model | Ошибка/retry по runtime-контракту, без вымышленного результата | Существующие lease/retry/terminal states |
| Отказ на approval | Отменённый процесс, без финального process artifact | `cancelled`; промежуточные outputs сохраняются согласно trace/retention |
| Approval ещё не принято | Ожидание, не успех | `waiting_approval`; конкретный срок и эскалация определяются операционной политикой |
| Человек принимает материал с оговорками | Сохранение оговорок и явное ограничение использования | Артефакт содержит полный review-output; accepted business outcome оценивается отдельно |
| Выполнение внешнего действия неизвестно | Сверка по operation ID, без слепого повтора | В этой поставке отсутствует действие; правило для будущего продолжения |
| Cancel/replay/компенсация | Согласно документированным границам runtime | [Process Builder](../process-builder-1.2.md); safe replay может повторять LLM-этапы и не обещает идентичный текст |

## Оценка качества и метрики

Сначала собрать ручной baseline на сопоставимых задачах, затем версионированный набор с ожидаемым результатом и запрещёнными исходами. Для вероятностных ответов использовать несколько испытаний на задачу, сохранять распределение и ошибки; правила и расчёты оценивать детерминированно, смысл — калиброванной экспертной проверкой. Различие task/trial/trajectory/outcome и сочетание graders описаны в [первичном руководстве по eval](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents). Это методика испытания, не результат измерения текущих шаблонов.

Минимальные классы для **каждого** процесса: нормальный вход; отсутствующий обязательный источник; противоречие; неверный формат; попытка изменить инструкцию через вход; ошибка исполнителя; отказ/задержка человека. Для внешних действий дополнительно: дубль, неизвестный исход, отмена во время действия и неуспешная компенсация. Количество примеров и trials задаётся владельцем eval по разнообразию/риску до пилота.

| Метрика | Определение | Условие применения |
|---|---|---|
| Принятие без доработки | Принятые без исправления / все проверенные результаты | Отдельно показать непроверенные и отклонённые |
| Фактическая корректность | Подтверждённые существенные утверждения / проверенные существенные утверждения | Единая рубрика, источник и reviewer |
| Успех процесса | Принятые результаты, удовлетворяющие всем обязательным AC / все задачи когорты | Completed само по себе не числитель |
| Время цикла | От поступления до принятия/отказа; медиана и p95, с отдельным временем очереди/approval | Незавершённые случаи показаны отдельно |
| Доля эскалаций | Задачи, переданные человеку из-за исключения / все задачи когорты | Не смешивать обязательное финальное approval и эскалацию |
| Стоимость принятого результата | Измеренные inference, review, retry и сопровождение / число принятых результатов | При нуле — N/A; неизвестные затраты не считать нулём |
| Снижение трудозатрат | Сопоставимый ручной baseline минус затраты подготовки, review и исправления | Граница расчёта, период и состав задач одинаковы |

Решение о допуске принимает владелец процесса на основании заданных заранее quality/time/cost gates. Reviewer-агент не может быть единственным оценщиком или согласующим. Тесты с подставленным worker output проверяют проводку данных и состояния; они не подтверждают точность LLM, юридическую/финансовую корректность или реальную экономию.

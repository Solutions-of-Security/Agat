# Устанавливаемый пакет «Внутренний отчёт» v1

Пакет `internal-report` устанавливает в выбранный проект процесс, три агента и коллекцию с двумя учебными документами. Предпросмотр, установка и запуск используют общий [USE-002 preflight](./scenario-preflight.md). Установка не означает готовность к выполнению и не подтверждает качество ответа модели.

## Установка и первый отчёт

1. Откройте **Процессы → Новый процесс → Готовый пакет: внутренний отчёт**. Прямая ссылка внутри приложения: `#processes?packId=internal-report`.
2. Просмотрите роли, источники, инструменты, правила и ожидаемые расчёты. Укажите точное имя локальной модели. По умолчанию — `qwen3:8b`; embeddings — `embeddinggemma`.
3. Нажмите **Установить пакет**. Создание ресурсов атомарно; отсутствие worker или готовых embeddings не мешает установке. Появятся три агента, опубликованная v1 процесса `Внутренний отчёт · <project-id>` и коллекция **Внутренний отчёт · учебные источники**. Суффикс проекта исключает конфликт с глобальным ограничением имён процессов в существующих БД.
4. Выполните действия в блоке **Готовность сценария** и нажмите **Проверить снова**. Ошибка проверки или старый ответ для другой модели не разрешают запуск.
5. Нажмите **Запустить пример**, когда доступно выполнение сейчас. Отдельный выбор **Ожидать готовности в очереди** разрешает постановку при временно недоступных ресурсах; он не обходит обязательные зависимости.
6. После трёх агентных этапов откройте запрос согласования. Проверьте ссылки, формулы и ограничения. Подтверждение сохраняет `internal-report.md`; отклонение не создаёт этот итоговый артефакт. Отчёт скачивается из результатов запуска.

Вернуться в установщик можно по той же ссылке. Прогресс установки хранится на сервере и переживает перезапуск. Повторная установка той же версии с той же моделью возвращает прежние ID, не создаёт дублей и не перезаписывает изменения пользователя. Другой manifest или модель требуют отдельного изменения конфигурации, а не скрытой переустановки. Если существующий объект проекта занимает имя агента/коллекции пакета, переименуйте этот объект и повторите установку; частичных ресурсов после ошибки не остаётся.

## Состав и границы

| Элемент | Содержание |
|---|---|
| Исследователь | Реестр фактов, дат, источников, пробелов и противоречий |
| Аналитик | Полный отчёт с периодами, таблицей, формулами, выводами и ограничениями |
| Проверяющий | Полный исправленный отчёт, проверка чисел и источников, явные неподтверждённые утверждения |
| Процесс | Старт → подготовка задания / исследователь → подготовка задания / аналитик → подготовка задания / проверяющий → решение человека → артефакт → завершение |
| Знания | Синтетическая таблица `SUPPORT-DEMO v1` и правила `REPORT-DEMO v1`; URI `urn:agat:internal-report:v1:requests` и `urn:agat:internal-report:v1:rules` |
| Tools | Встроенные retrieval, transform и artifact; внешние MCP tools не требуются |
| Исполнение | Существующий runtime процессов и локальный worker `single/tool_loop_v1` с выбранной моделью и embeddings |
| Политики | Обязательная коллекция в графе; пустой MCP allowlist; решение человека в полном процессе; никакой автоматической выдачи secrets/scopes |

Требования знаний закреплены в `graph.requiredKnowledgeCollectionIds`. API запуска по умолчанию выбирает их; явное исключение блокирует даже очередь. `graph.mcpToolAllowlist: []` ограничивает и выдаваемые worker инструменты, и разрешение инструментов gateway: подделанный запрос запрещён. Существующие MCP-подключения проекта не становятся доступными этому процессу. Установка не меняет общую policy проекта и не запрещает инструменты другим процессам. `allowPartialStart: false` блокирует обход согласования запуском с произвольного шага; тестирование отдельных узлов не считается полным запуском пакета.

Проверка фактической истинности остаётся задачей проверяющего и человека. В v1 нет формального валидатора утверждений, облачного профиля, экспорта PDF/DOCX, автоматического обновления/rollback пакета или qualification настоящей LLM. Учебные CSV-данные устанавливаются как текстовый источник через существующий ingestion; файловые импортеры не требуются для этого примера. Тест отдельных узлов и пользовательские изменения схемы — отдельные сценарии, а не подтверждённый полный проход установленного пакета.

## Зависимости и восстановление

| Причина в preflight | Точное действие |
|---|---|
| Пакет отсутствует | Установить на текущем экране; предпросмотр ничего не создаёт |
| Нет worker нужного runtime | **Подключить совместимый worker** открывает узлы с `runtime=single&profile=tool_loop_v1` |
| На worker нет модели | **Настроить модели команды** передаёт точные `model` и `nodeId`; установите указанную модель на этот worker |
| Нет индексированных фрагментов / embeddings | Ссылка открывает конкретную коллекцию; проверьте документы и ошибки индексации, подключите worker с `embeddinggemma`, дождитесь статуса готовности |
| Agent worker не поддерживает embeddings | **Подключить embeddings на worker агента** передаёт `embeddingModel=embeddinggemma` |
| Обязательная коллекция удалена | Создайте и индексируйте замену в **Знаниях**; ссылка ведёт в **Готовность → Обязательные коллекции процесса**. Замените привязку, сохраните, опубликуйте и запускайте новую версию из редактора |
| Runtime недоступен / очередь заполнена | Ссылка ведёт в runtime или policy проекта; восстановите runtime либо освободите квоту |
| Ресурсы заняты | Дождитесь освобождения и повторите проверку либо явно выберите очередь |
| Раздел недоступен вашей роли | Скопируйте адрес настройки администратору и укажите текущий проект |

В установщике закреплена именно установленная версия процесса. Позднейшая публикация пользовательской v2 не подменяет v1 при запуске примера. Новые версии запускаются из редактора. Изменение знаний, определений агентов или графа требует нового успешного полного прохождения для `scenarioVerified`.

## API и хранение

| Запрос | Контракт |
|---|---|
| `GET /api/v1/process-packs` | Один manifest, включая граф с placeholders ролей/коллекции, SHA-256 и установку текущего проекта либо `null` |
| `POST /api/v1/process-packs/internal-report/preflight` | `{version: 1, manifestSha256, model}` → `{manifest, installation, preflight}`; read-only |
| `POST /api/v1/process-packs/internal-report/install` | То же тело; `201` при создании, `200` при повторе; роли `admin`/`designer` |
| `POST /api/v1/processes/:id/preflight` | Обычный USE-002 с `version` и коллекциями установки |
| `POST /api/v1/processes/:id/start` | `input`, закреплённая `version`, `startMode: now/queue`, `knowledgeCollectionIds`; повторный preflight в транзакции, при блокировке `409` и актуальный `preflight` |

`manifestSha256` покрывает данные, инструкции, зависимости, policy и граф. Установка хранит pack/version/digest/model, ID созданных ресурсов, версию процесса и время в `process_pack_installations`, ключ — `(project_id, pack_id)`. Событие `process.pack.installed` содержит provenance установки. Для PostgreSQL есть tenant policy и блокировка строки проекта на время установки; перед обновлением runtime примените текущую [schema migration Job](./postgresql-migration-job-runtime-role.md). Для SQLite используется существующая транзакционная миграция. Поля требований сохраняются при копировании, публикации, BPMN round-trip и отображаются в version diff.

## Сквозные проверки

Все новые тесты находятся в `/docs/tests`:

```sh
npm run test:process-pack
npm run test:process-pack:ui
```

Первый набор входит в `npm test`. Он использует настоящие HTTP API, SQLite, scheduler, retrieval, approval и Artifact Store; моделирование ограничено ответами worker и embeddings. Проверяются чистая установка, read-only preview, авторизация, изоляция двух проектов, stale manifest, конкурентные повторы, отсутствие частичной установки, восстановление после рестарта, недостающие модели/знания, защита MCP gateway, отрицательное согласование, скачивание отчёта и evidence drift.

Браузерный тест собирает production frontend в временный каталог, запускает временный coordinator и проверяет desktop 1440×1100 и mobile 390×844: установка, блокировка старта, переход к конкретной коллекции, возврат без дублей, повторная проверка, запуск примера, согласование и скачивание. Проверяются заголовок страницы, содержимое, отсутствие framework overlay, ошибки console/pageerror и ширина диалога. Скриншоты `agat-pack-<viewport>-overview/blocked/ready.png` сохраняются в системный временный каталог.

Для UI-теста нужен Playwright с Chromium. Можно использовать уже установленный runtime без изменения зависимостей проекта:

```sh
AGAT_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
AGAT_BROWSER_PATH=/absolute/path/to/chromium \
npm run test:process-pack:ui
```

Без переменных используется пакет `playwright` из среды и его стандартный Chromium. Использованный путь проверки: Browser plugin not available → Playwright / локальный Chrome. Настоящие LLM, Temporal и PostgreSQL не подменяются статусом «проверено»: их эксплуатационная квалификация остаётся отдельной проверкой.

Проверено 19 сентября 2026:

| Проверка | Результат |
|---|---|
| Typecheck coordinator и web | Пройден |
| Регрессия coordinator / web | 169 / 41 тест пройден; внешние инфраструктурные suites требуют отдельных стендов |
| Финальная выборка pack + USE-002 + Process Builder + каталог | 38 тестов пройдено |
| Production UI, Chrome, 1440×1100 и 390×844 | Оба сквозных сценария пройдены |
| Содержимое страницы, framework overlay, console/pageerror, действия и геометрия диалога | Пройдено; desktop/mobile скриншоты просмотрены |

Браузерная проверка выявила конфликт глобального имени процесса между проектами и слишком узкое поле режима запуска на mobile. Установщик теперь добавляет суффикс проекта, а мобильные действия располагаются вертикально; оба исправления перепроверены. В проверках не выполнялась генерация настоящей LLM: проверены интеграция и контроль выполнения, а качество текста требует отдельного прогона модели на контрольном результате выше.

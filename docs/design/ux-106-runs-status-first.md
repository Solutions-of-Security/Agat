# UX-106: status-first workspace запусков

Дата фиксации: 31 августа 2026 года.

## Цель

Экран запуска должен за несколько секунд отвечать на четыре вопроса: что происходит, на каком этапе находится выполнение, требуется ли действие пользователя и какой результат уже доступен. Технические данные не удаляются, но перестают конкурировать с операторским сценарием.

## Визуальные ориентиры

- [Desktop-концепт](./agat-runs-status-first-desktop.png)
- [Mobile-концепт](./agat-runs-status-first-mobile.png)

Концепты используются как ориентир по иерархии, плотности и responsive-поведению. В runtime не добавлены растровые assets: интерфейс собран существующими компонентами, CSS и SVG-иконками АГАТ.

## Информационная архитектура

Desktop использует master-detail:

1. компактный список запусков показывает название, статус, время и прогресс;
2. выбранный запуск открывается справа без повторной страницы-таблицы;
3. status summary показывает состояние, текущий этап, длительность, прогресс и допустимое действие;
4. решение по согласованию находится сразу после summary;
5. этапы показывают только название и состояние;
6. результат и ошибка доступны до технического слоя;
7. trace, входы, артефакты, manifest, Replay / Eval и scheduler policy находятся в закрытых по умолчанию `Технических деталях`.

Mobile разделяет list и detail. Базовый `#runs` показывает список; выбор создаёт deep link и открывает отдельный detail-экран с кнопкой `Все запуски`. Так таблица и подробности не складываются в одну длинную страницу.

## Состояния и действия

| Состояние | Основное сообщение | Действие |
|---|---|---|
| `queued` | Запуск ожидает планировщик | `Остановить` для изменяющих ролей |
| `running` | Текущий агент и автоматически обновляемый статус | `Остановить` |
| `waiting_approval` | Требуется решение оператора | `Разрешить` / `Отклонить`; остановка остаётся вторичной |
| `waiting_external` | Ожидается внешнее событие | `Остановить` |
| `compensating` | Идёт безопасная компенсация | Только наблюдение |
| `completed` | Результат готов | `Открыть результат`, `Повторить` для agent-only run |
| `failed` | Видна последняя ошибка | `Повторить`, если replay безопасен |
| `cancelled` | Выполнение остановлено, данные сохранены | `Повторить`, если replay безопасен |

Недоступный replay остаётся видимым только в терминальном состоянии и сопровождается причиной: недостаточная роль либо наличие process/внешних шагов. Во время сетевой операции label сообщает текущее действие.

Остановка использует встроенное двухшаговое подтверждение, а не системный `window.confirm`. API `POST /api/v1/runs/:id/cancel` применяет тот же project scope и RBAC, что создание/replay; для process run дополнительно уведомляется durable runtime.

## Shareable route

- список: `#runs`;
- запуск: `#runs/<encoded-run-id>`;
- согласование конкретного запуска: `#approvals/<encoded-run-id>`.

Back/forward восстанавливают выбранный запуск. Reload сохраняет detail. Устаревший или неизвестный run ID безопасно заменяется базовым маршрутом без ложного соответствия URL и открытого объекта.

## Progressive disclosure

Полный trace запрашивается только после открытия `Технических деталей`. До этого status summary и результат используют уже загруженный overview, поэтому ежедневный экран не платит стоимость технического запроса и не показывает промежуточный loading chrome. После раскрытия остаются существующие фильтры журнала, экспорт, входы/output, артефакты, manifest, eval и policy.

## Доступность и responsive

- list item является одной кнопкой с `aria-current` для выбранного запуска;
- list filters и technical tabs используют общий roving-tab pattern;
- disclosure реализован нативным `details/summary`;
- result получает программный focus при действии `Открыть результат`;
- подтверждение остановки — именованная группа с двумя явными исходами;
- controls сохраняют минимум 44×44 px;
- на 390×844 список и detail взаимоисключающие, approval больше не фиксируется поверх содержимого;
- исправлен отсутствующий React `key` у общего tabs-компонента, поэтому console-smoke проходит без warning/error.

## Отличия реализации от концепта

- Постоянный notification rail из desktop-концепта не перенесён: рабочие уведомления уже доступны в глобальной панели topbar, а второй rail снова перегрузил бы экран.
- Демо-текст `Собираем факты и формируем выводы` заменён state-aware сообщениями, чтобы UI не утверждал несуществующую семантику конкретного агента.
- Mobile-концепт показывает завершённый запуск, а проверочный fixture — состояние согласования; компоновка поддерживает оба состояния, но главное действие выбирается по фактическому status.
- `Открыть результат` показывается только для `completed`; промежуточный output остаётся в result preview без конкурирующего primary action.

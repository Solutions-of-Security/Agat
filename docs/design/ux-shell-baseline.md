# Operator UX foundation: shell, уведомления и доступность

Дата фиксации: 31 августа 2026 года. Документ описывает реализованную основу задач UX-101–UX-105 и проверяемые ограничения двух инкрементов.

## Цель

Сделать ежедневные действия заметнее инфраструктурных настроек, сократить первый уровень навигации и сохранить экспертные функции через ролевые группы. Shell, рабочие уведомления и базовый accessibility gate закрыты. Изменения не закрывают весь релиз 1.8: status-first Runs, полный inbox согласований и трёхшаговый запуск остаются отдельными задачами.

## Ролевая информационная архитектура

У всех ролей первый уровень начинается с `Обзор`, `Запуски`, `Согласования`. Остальные разделы раскрываются в группах `Создание` и `Администрирование`; недоступный раздел не показывается и не открывается прямым hash-переходом.

| Роль | Создание | Администрирование | Изменяющие действия |
|---|---|---|---|
| `admin` | Агенты, Процессы, Знания, Качество | Узлы, Модели, Fleet / HA, MCP, A2A | Все действия, включая scheduler и решения по согласованиям |
| `designer` | Агенты, Процессы, Знания, Качество | MCP, A2A | Проектирование, запуск и replay; без scheduler и решений по согласованиям |
| `operator` | Знания, Качество | MCP, A2A | Запуск, replay и решения по согласованиям; без проектирования |
| `viewer` | — | — | Только чтение |
| `auditor` | Знания, Качество | Узлы, Fleet / HA, MCP, A2A | Только чтение |

Единая функция capability-матрицы используется shell и экраном запусков. Для `viewer` и `auditor` не рендерятся создание запуска, replay, управление scheduler и кнопки принятия решения.

## Desktop и mobile

Desktop:

- три прямых рабочих раздела;
- до двух раскрываемых ролевых групп;
- breadcrumbs между topbar и содержимым;
- `Создание` раскрыто по умолчанию, `Администрирование` — только по запросу или при активном дочернем разделе;
- Node Rail остаётся только на `Обзоре` и не дублирует страницу `Запуски`.

Mobile:

- один фиксированный ряд максимум из пяти целей: `Обзор`, `Запуски`, `Согласования`, ролевой закреплённый раздел, `Ещё`;
- для `admin` и `designer` закреплены `Процессы`, для `operator` — `Знания`, для `auditor` — `Качество`; у `viewer` остаются три доступных прямых раздела без пустых или недоступных кнопок;
- `Ещё` открывает ролевой bottom sheet со всеми разрешёнными разделами, закрывается по backdrop и Escape;
- нижняя навигация учитывается в высоте process editor и не перекрывает конечные действия.

Отличие от раннего mobile-концепта осознанное: вместо абстрактного пункта `Создать` используется конкретный ролевой раздел из утверждённого UX-102.

## Topbar и читаемость

- глобальные метрики очереди, узлов и агентов убраны из topbar;
- остаются selector проекта, один контекстный CTA, рабочая панель уведомлений и меню профиля;
- logout выполняется явным пунктом меню, а не кликом по аватару;
- для стандартных `.section-page` основной текст установлен не меньше 14 px, вторичный — не меньше 12 px;
- интерактивные цели имеют минимум 44×44 px;
- строка Fleet worker описана семью явными grid-колонками и перестраивается на tablet/mobile без auto-column шириной в несколько пикселей.

Допустимое исключение — масштабируемое содержимое Process canvas: подписи узлов и технический monospace могут визуально уменьшаться вместе с canvas. Исключение не распространяется на toolbar, диалоги, формы и основные действия. Для окончательного gate нужен отдельный populated-process fixture; пустое состояние не подтверждает читаемость всех типов узлов.

## Панель уведомлений

- источник не имитируется: лента строится из ожидающих решения approvals и последних `warn/error` событий coordinator;
- одно событие согласования не дублируется соответствующим warning из журнала;
- непросмотренные ID хранятся отдельно для каждого проекта в `localStorage`; содержимое запуска и события туда не записывается;
- доступны явное действие `Прочитать всё`, статус через `aria-live`, история просмотренных событий и переход из строки к точному run/approval;
- мобильная и desktop-панель рендерятся portal-слоем в `document.body`, поэтому `backdrop-filter` и stacking context topbar не смещают overlay;
- mobile drawer занимает viewport с отступом 8 px и не перекрывается bottom navigation.

Server-side синхронизация seen-state между устройствами не требуется roadmap-задачей UX-103 и остаётся возможным последующим расширением.

## Accessibility foundation

- skip link — первый элемент tab order; активация переносит не только прокрутку, но и фокус на `#main-content`;
- единый tabs-компонент задаёт `tablist/tab/tabpanel`, `aria-selected`, `aria-controls` и roving `tabIndex`; поддержаны `ArrowLeft/Right`, `Home` и `End`;
- паттерн применён к detail запуска, mobile-очереди, Quality, Process Inspector и release-панели;
- кастомные overlays используют общий focus trap, блокировку background scroll, Escape и возврат фокуса к trigger;
- mobile sheet `Ещё` использует тот же focus-management contract;
- нативные `<dialog>` получили устойчивые accessible names через `aria-labelledby`;
- недоступный `Новый experiment` сопровождается видимым prerequisite вместо необъяснимого disabled control.

## Проверка

Автоматизированный DOM-smoke выполнен для 12 маршрутов (`Обзор`, `Запуски`, `Согласования`, `Агенты`, `Процессы`, `Знания`, `Качество`, `MCP`, `A2A`, `Узлы`, `Модели`, `Fleet / HA`) на ширинах 390, 768 и 1440 px — всего 36 комбинаций.

Результат:

- horizontal overflow: 0 во всех 36 комбинациях;
- видимый текст меньше 12 px в стандартных section pages: 0;
- видимые интерактивные цели меньше 44 px по ширине или высоте: 0;
- mobile viewport: 390×844, пять пунктов по 78×75 px в одной строке; labels 12 px и не обрезаются;
- меню `Ещё`: видимый `role="dialog"`, все девять admin-разделов доступны;
- desktop smoke в нативном viewport встроенного браузера 1280×720: все маршруты открываются, ошибок и предупреждений console нет.

Встроенный браузер использован для нативного desktop smoke и интерактивных переходов. Его команда изменения viewport не применилась (`window.innerWidth` оставался 1280), поэтому responsive-проверка 390/768/1440 выполнена тем же production build в локальном headless Chromium через DevTools Protocol с отключённым кэшем.

### Повторная проверка UX-103/UX-105

Проверка выполнена на production build с demo coordinator:

- `npm run typecheck --workspace @agat/web` — успешно;
- `npm run test:web` — 10/10 тестов, включая keyboard-модель tabs и project-scoped seen/unseen уведомлений;
- `npm run build --workspace @agat/web` — успешно;
- встроенный Browser, 1280×720: панель открывается, первый фокус попадает на close, Tab/Shift+Tab замыкаются внутри, Escape закрывает панель, снимает scroll lock и возвращает фокус кнопке уведомлений;
- переход из action-notification открывает `#approvals` и нужный запуск `Отчёт по продажам`;
- `ArrowRight` и `End` меняют выбранный tab, roving `tabIndex` и единственный видимый `tabpanel`;
- встроенный Browser, 390×844: viewport применён, drawer имеет фактический rect 374×828 px, horizontal overflow равен 0, видимых кнопок меньше 44×44 px нет;
- mobile sheet `Ещё`: focus trap работает в обе стороны, Escape возвращает фокус кнопке `Ещё`;
- локальный headless Chrome через DevTools Protocol: первый Tab выбирает skip link, Enter переносит фокус в `#main-content`; Enter открывает нативный dialog, Escape закрывает и возвращает фокус кнопке `Новый запуск`;
- browser console: 0 warning/error.

DevTools Protocol использован только для нативных default actions Enter/Escape: API встроенного Browser фокусировал locator, но не выполнял browser default action этих клавиш. Responsive-проверка второго инкремента прошла непосредственно встроенным Browser; временный viewport после теста сброшен.

Интерактивная проверка выявила и исправила два дефекта до фиксации результата: skip link первоначально менял только scroll position, а mobile drawer попадал в containing block topbar и уходил выше viewport. После исправлений оба сценария перепроверены.

Не входят в этот gate: populated Process canvas, реальные iOS/Android устройства, screen reader и usability-test 4/5. Эти проверки остаются в UX-204 и release gate 1.8.

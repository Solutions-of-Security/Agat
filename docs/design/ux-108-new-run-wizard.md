# UX-108: трёхшаговое создание запуска

Дата фиксации: 1 сентября 2026 года.

## Цель

Пользователь создаёт запуск без одновременного разбора всех параметров планировщика. Базовый путь последовательно отвечает на три вопроса: что выполнить, кто выполнит и можно ли запускать. Экспертные параметры остаются доступны, но не конкурируют с основным решением.

## Базовый путь

### 1. Задача

На экране находятся только:

1. `Название запуска`;
2. `Задача и входные данные`.

Кнопка `Далее: цепочка` проверяет оба поля и переводит фокус на заголовок второго шага. Значения сохраняются при возврате назад.

### 2. Цепочка

- выбранные агенты показаны отдельной упорядоченной последовательностью;
- порядок меняется явными кнопками `Выше` и `Ниже`, поэтому drag-and-drop не является единственным способом;
- агент удаляется отдельной подписанной кнопкой;
- доступные агенты добавляются одним действием;
- при обычном входе выбирается только один первый агент, а не все встроенные агенты;
- при входе из карточки агента сохраняется переданный `initialAgentIds`;
- знания находятся в disclosure `Подключить знания · необязательно`.

Переход к проверке доступен только при наличии хотя бы одного агента.

### 3. Проверка и запуск

Сначала показывается summary задачи, цепочки и знаний. Затем пользователь принимает три базовых решения:

- режим: `Последовательно`, `Авто`, `Параллельно`;
- приоритет: `Обычный`, `Высокий`, `Срочный`;
- результат: `Только в журнале` или `Журнал + Artifact Store`.

Значения приоритета presets: `Обычный = 50`, `Высокий = 75`, `Срочный = 100`.

`Только в журнале` является безопасным default. Artifact Store не включается без явного выбора и объясняет, что создаст файлы каждого этапа.

## Расширенные настройки

Закрытый по умолчанию disclosure содержит:

- точное числовое значение priority `0–100`;
- подтверждение финального этапа, включённое по умолчанию;
- относительный каталог Artifact Store, только если выбран соответствующий destination.

До раскрытия advanced пользователь видит не более семи решений: название, задача, цепочка, optional knowledge, режим, priority preset и destination.

## Состояние и API

Wizard хранит draft локально до отправки. Финальный payload сохраняет действующий контракт `CreateRunRequest`:

| UI | API |
|---|---|
| Название | `name` |
| Задача | `input` |
| Порядок цепочки | `agentIds` |
| Знания | `knowledgeCollectionIds` |
| Режим | `executionMode` |
| Priority preset / число advanced | `priority` |
| Подтверждение | `approvalRequired` |
| Результат | `resultDestination` |
| Каталог | `artifactPath` |

Backend-контракт не меняется.

## Дизайн-система

- фон и surfaces: действующие `--bg-deep`, `--surface-raised`;
- borders: `--line` и `--line-soft`, без дополнительной вложенной сетки карточек;
- accent: `--lime` только для current/completed step, выбранного значения и primary CTA;
- typography: заголовок 24 px desktop / 22 px mobile, основной текст не меньше 14 px, secondary не меньше 12 px;
- controls: минимум 44×44 px;
- радиусы и SVG-иконки наследуются из текущего shell;
- footer остаётся видимым, но не перекрывает scrollable content.

## Доступность и responsive

- progress — именованный `ol`, текущий шаг имеет `aria-current="step"`;
- при смене шага фокус переносится на его заголовок;
- ошибки связаны с полями через `aria-describedby` и выводятся как `role="alert"`;
- reorder доступен с клавиатуры отдельными кнопками;
- disabled reorder/actions имеют недоступное состояние, но не исчезают неожиданно;
- Escape закрывает native dialog;
- на mobile dialog становится полноэкранным flow, footer и bottom navigation не перекрывают финальное действие;
- на 390 px не допускается horizontal overflow.

## Проверочный сценарий

`Новый запуск → заполнить задачу → изменить цепочку и порядок → открыть/закрыть знания → выбрать режим, приоритет и destination → проверить advanced → запустить → открыть созданный run`.

## Реализация

- `NewRunDialog.tsx` управляет шагами, фокусом, inline-ошибками, reorder, progressive disclosure и финальной readiness-проверкой;
- `newRunFlow.ts` изолирует выбор безопасных defaults, перестановку цепочки, mapping priority и сборку `CreateRunRequest`;
- `new-run-flow.test.ts` проверяет default одного агента, переданный порядок без дублей, immutable reorder, границы priority и очистку `artifactPath` для результата только в журнале;
- backend-контракт не менялся: wizard отправляет существующий `CreateRunRequest`.

## Сверка концепта и реализации

Сохранены ключевые признаки концепта:

1. один именованный progress из трёх шагов вместо единой длинной формы;
2. на первом шаге остаются только название и задача;
3. цепочка показана в порядке выполнения и меняется явными кнопками;
4. review начинается со сводки и использует понятные presets режима, приоритета и результата;
5. lime используется только для состояния шага, выбранных значений и primary action;
6. footer отделён от scrollable content и остаётся доступен на desktop и mobile.

Copy перенесён без смысловых расхождений. В реализации добавлены прикладные подсказки `детали можно уточнить позже`, `порядок выполнения задаётся сверху вниз`, readiness-текст и объяснение безопасного journal-default.

Осознанные отличия:

- концепт показывает весь mobile review одной высокой композицией; реальный viewport 390×844 сохраняет 14/12 px и touch targets ≥44 px, поэтому середина шага прокручивается, а финальные действия остаются закреплены;
- bottom navigation остаётся зарезервирована по высоте, но затемняется native modal backdrop и недоступна до закрытия wizard — это сохраняет модальность и не создаёт ложных доступных действий;
- используются существующие AGAT SVG-иконки и production tokens, без переноса иллюстративных деталей концепта.

## Проверка реализации

Проверка выполнена 1 сентября 2026 года на актуальном frontend-коде:

- `npm run typecheck` — успешно;
- `npm test` — 16/16 тестов успешно;
- `npm run build` — успешно, Vite собрал 219 модулей;
- встроенный Browser: desktop 1280×720 и mobile 390×844;
- desktop dialog: 820×688 px, horizontal overflow отсутствует;
- mobile dialog: 390×780 px над зарезервированными 64 px bottom navigation, horizontal overflow отсутствует;
- все измеренные действия цепочки на mobile не меньше 44×44 px;
- initial focus попадает в название, переходы фокусируют заголовок шага, закрытие кнопкой возвращает фокус в `Новый запуск`;
- inline-валидация возвращает обе связанные ошибки для пустого первого шага;
- console errors отсутствуют.

Полный сценарий выполнен на локальном mock API с тремя агентами и одной готовой knowledge-коллекцией. Итоговый payload подтвердил порядок `Редактор → Сборщик → Аналитик`, `executionMode=auto`, точный `priority=83`, выключенное подтверждение, выбранную knowledge-коллекцию и пустой `artifactPath` после возврата с Artifact Store к journal-only. После создания открылся shareable route `#runs/run-qa-108`.

Ограничения проверки:

- mock подтверждает frontend/API mapping, но не заменяет e2e с реальным coordinator и worker;
- встроенный Browser не выполнил browser default action для `Escape` через automation API; native `dialog`/`onCancel` contract сохранён, а close/focus-return проверен интерактивно;
- реальные iOS/Android, screen reader и operator usability-test остаются частью release gate 1.8;
- clean-copy QA использован из-за iCloud-dataless placeholders в локальном `node_modules` и нескольких неизменённых исходниках workspace; проверялся тот же текущий UX-108 source.
